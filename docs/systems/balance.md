# ปรับสมดุล (ค่าอาชีพ tier ของไอเทม และมอนธรรมดา)

แท็บ **"ปรับสมดุล"** ใน `/admin` ใช้แก้ตัวเลขเกมของทั้งเซิร์ฟโดยไม่ต้องแก้โค้ด (เจ้าของตกลง 2026-11-11)

## ปรับอะไรได้

- **ค่าอาชีพ** แยกนักดาบ เวทย์ และมือปืน ทุกสเตตัส 10 ตัว (HP, MP, ATK, DEF, คริ, ดาเมจคริ, ตีเร็ว, วิ่งเร็ว, ฟื้น HP, ฟื้น MP)
  - **Lv1** (`base`)
  - **ต่อเลเวล** (`growth`): ทุกสเตตัส รวมคริ ดาเมจคริ ตีเร็ว และวิ่งเร็ว ที่ในโค้ดเป็น 0
  - **ตัวคูณ** (`statMult`): คูณค่ารวมทั้งอาชีพ เลเวล และของใส่ เช่นนักดาบ HP/ATK/DEF ×2
  - **ดาเมจใส่บอส** (`bossDmgMult`): ไม่รวมลูกน้องที่บอสเรียก
  - **MP สกิลเพิ่ม % ต่อเลเวล** (`mpCostPerLevel`): ดูหัวข้อ "MP ของสกิลตามเลเวล" ข้างล่าง
- **ตัวตัดฟื้นทั้งเกม:** ฟื้น HP ×0.4 และฟื้น MP ×0.25 ใช้หลังตัวคูณอาชีพ จึงตัดค่าฟื้นจากของใส่ด้วย
- **Tier T1–T5:**
  - น้ำหนักโอกาส (3/9/18/30/40)
  - ความกว้างของแต่ละ tier เป็น % (25/25/25/15/10 รวมกันต้องได้ 100)
  - ค่าต่ำสุดของช่วง (40% ของค่าสูงสุด)
  - บอสเพิ่มโอกาส tier ดี (1.5)
- **ตาราง tier แยกต่อสเตตัส** (เจ้าของตกลง 2026-11-11): ทุกสเตตัสบนไอเทม (ATK, DEF, HP, MP, คริ, ดาเมจคริ, ตีเร็ว, วิ่งเร็ว, ฟื้น HP/MP) ตั้งตารางของตัวเองได้ ครบ 4 อย่างเหมือนตารางกลาง: น้ำหนักโอกาส, ความกว้าง, ค่าต่ำสุด, บอสเพิ่มโอกาส tier ดี
  - สเตตัสที่ไม่ได้ตั้งเองใช้ **ตารางกลาง** · ในโค้ดทุกสเตตัสใช้ตารางกลาง (ไม่มีค่าเริ่มต้นแยก)
  - ช่วงค่ายังโตตามเลเวลไอเทมเหมือนเดิม (ตารางเป็น % ของช่วง ไม่ใช่ตัวเลขตายตัว)
- **ตาราง tier ตามช่วงเลเวลไอเทม** (เจ้าของตกลง 2026-11-11): ช่วงตายตัวตามแมพ Lv1–10 / 11–20 / 21–30 / 31–40 / 41–50 (`TIER_BANDS` ใน `items.ts`) ดูจาก**เลเวลของไอเทม**
  - ตั้งได้ทั้ง "ทุกสเตตัสในช่วงเลเวล" และ "สเตตัส × ช่วงเลเวล" (ซ้อนกับตารางต่อสเตตัส)
  - แต่ละส่วน (โอกาส ความกว้าง ค่าต่ำสุด บอสเพิ่ม tier) ใช้ของตารางแรกที่ตั้งไว้ตามลำดับ: **สเตตัส+ช่วงเลเวล → สเตตัสทุกเลเวล → ทุกสเตตัสในช่วงเลเวล → ตารางกลาง**
  - ในโค้ดไม่มีตารางตามช่วงเลเวล (ทุกอย่างใช้ตารางกลาง)
  - การสุ่มที่ช่างตีเหล็กใช้ตารางของสเตตัสนั้น · ตารางโอกาสของช่างตีเหล็ก (สุ่มสเตตัส) ยังมีแถว T1–T5 แถวเดียว คือโอกาสจริงรวมทุกสเตตัสที่อาจได้บนไอเทมนั้น
- **หน้าจอ:**
  - แสดงค่าจริงตอน Lv1/10/50 แบบไม่ใส่ของ ใช้ฟังก์ชันเดียวกับ server (`classStatsAt`)
  - แสดงโอกาสแต่ละ tier ทั้งของมอนปกติและของบอส
  - ช่องที่ต่างจากค่าในโค้ดเป็นสีทอง ชี้ค้างไว้เพื่อดูค่าในโค้ดและช่วงที่ใส่ได้
  - การ์ด tier มี "ตารางกลาง" แล้วต่อด้วย "ตารางแยกต่อสเตตัส": dropdown เลือกสเตตัส (ที่ตั้งเองมีคำว่า "(ตั้งเอง)") + รายชื่อสเตตัสที่ตั้งเองอยู่
    - สเตตัสที่ยังใช้ตารางกลาง: ปุ่ม "ตั้งตารางเองสำหรับสเตตัสนี้" (เริ่มจากค่าตารางกลางตอนนั้น)
    - สเตตัสที่ตั้งเอง: ตารางหน้าตาเดียวกับตารางกลาง + ปุ่ม "กลับไปใช้ตารางกลาง"
  - (เพิ่ม 2026-11-11) ตัวเลือกมี 2 ช่อง: **สเตตัส** (ทุกสเตตัส / แต่ละตัว) × **ช่วงเลเวล** (ทุกเลเวล / 5 ช่วง) · ยังไม่ได้ตั้งจะบอกว่า "ตอนนี้ใช้: ..." และปุ่มตั้งเองเริ่มจากค่าที่ใช้อยู่ตอนนั้น · ปุ่ม "เลิกตั้งตารางนี้" กลับไปใช้ตารางที่ครอบอยู่
  - **การ์ด "ตัวอย่างค่าจริงที่สุ่มได้"**: เลือกชนิดไอเทม ความหายาก และเลเวลไอเทม แล้วเห็นช่วง T1–T5 เป็นตัวเลขจริงของทุกสเตตัส (หลัก ล็อก และเสริมทุกตัว) พร้อมบอกว่าใช้ตารางไหน · ชี้ค้างที่ช่องดูโอกาส tier นั้น (ปกติ/บอส) · คิดจากค่าที่กำลังแก้อยู่ ยังไม่บันทึกก็เห็น

## MP ของสกิลตามเลเวล (เจ้าของตกลง 2026-11-13)

- **สูตร:** MP ที่ใช้ = `mp` ในโค้ด (`classes.ts`) × (1 + k × (เลเวล − 1)) โดย k = "% ต่อเลเวล" ของอาชีพนั้น
  - ค่าในโค้ด **3% ทุกอาชีพ** (`MP_COST_PER_LEVEL` ใน `classes.ts`): Lv20 ×1.57, Lv40 ×2.17, Lv50 ×2.47 เช่นลูกไฟ Lv1 10 → Lv20 16 → Lv40 22 → Lv50 25
  - สกิลที่ `mp: 0` (โจมตีปกติ, พุ่ง) ยังเป็น 0 · ตั้ง 0% = MP เท่าในโค้ดทุกเลเวล
  - **ปัดเศษ:** ปัดเป็นจำนวนเต็มที่ใกล้สุด (`Math.round` .5 ปัดขึ้น)
- **เหตุผล:** เลเวลสูงไม่มีใครกดยา MP เพราะ MP ของสกิลคงที่ แต่ MP สูงสุดและการฟื้น MP โตตามเลเวล ถ้ากดสกิลทุกตัวทันทีที่คูลดาวน์หมด (ไม่นับของที่ใส่) MP หมดใน 25 วิ ตอน Lv1 แต่ใช้ได้ 134–364 วิ ตอน Lv50 · ใช้ 3% ทุกเลเวลจะเหลือราว 20–40 วิ ใกล้เคียง Lv1
- **ใช้ที่ไหน:** ฟังก์ชันเดียว `skillMpCost` ใน `balance.ts` (เรียกผ่าน `Player.skillMp`) ใช้ทั้งตอนเช็คว่า MP พอไหมและตอนหัก MP (`Player`), Auto Play (ใช้สกิลเมื่อ MP ≥ ค่าใช้ + 5), กล่องข้อมูลสกิลในเกม และปุ่มสกิลสีเทาตอน MP ไม่พอ (`nomp` ทั้งคอมและมือถือ)
- **ปรับได้:** ช่อง "MP สกิลเพิ่ม % ต่อเลเวล" ในการ์ดอาชีพ แยกนักดาบ/นักเวท/มือปืน ช่วง **0–20%** (ช่วงที่เสนอไว้ เจ้าของเปลี่ยนได้) พร้อมตัวอย่างค่าจริงของทุกสกิลที่ใช้ MP ที่ Lv1/20/40/50
  - เก็บใน `classes.<อาชีพ>.mpCostPerLevel` เฉพาะเมื่อต่างจาก 3 · audit แบบ `MP สกิล/เลเวล นักเวท 3% → 4%` · "คืนค่าในโค้ด" กลับเป็น 3% · มีผลทันที (เบราว์เซอร์ได้ค่าผ่านข้อความ `balance`)

## ตัวคูณค่าสเตตัสบนไอเทม (เจ้าของตกลง 2026-11-11)

- **คืออะไร:** สเตตัสละ 1 ตัวคูณ (เช่น วิ่งเร็ว ×0.75 = ลด 25%) ใช้กับ**ทุกบรรทัด**ของสเตตัสนั้นบนไอเทม (หลัก ล็อก เสริม) ทุกเลเวล ทุก tier ทุกชนิดไอเทม · ช่วง ×0.1–×10 · ไม่ตั้ง = ×1
- **หน้าจอ:** อยู่ในการ์ด "ตัวอย่างค่าจริงที่สุ่มได้"
  - ใส่ตัวคูณ แล้วกด **"ทดลอง"** ตารางจะแสดง `ช่วงเดิม → ช่วงใหม่` (ไฮไลต์) ยังไม่มีผลอะไร · ใครมีสวิตช์ `balance` ก็ทดลองได้
  - กด **"คอนเฟิร์ม คูณทั้งเซิร์ฟ"** ถึงจะมีผลจริง · เฉพาะสวิตช์ `itemStatMult` (owner เท่านั้น) · API `POST /api/admin/balance/item-mult`
  - ปุ่ม "บันทึกทั้งเซิร์ฟ" และ "คืนค่าในโค้ด" ปกติ**ไม่แตะตัวคูณ** (server ใส่ตัวคูณที่ใช้อยู่กลับเข้าไปเอง)
- **ผลหลังคอนเฟิร์ม** (ทำต่อกันในครั้งเดียวโดยไม่หยุด จึงไม่มีเทรด/ซื้อขายตลาด/เซฟแทรกกลางทาง):
  1. สำรอง DB อัตโนมัติ (backup ชนิด `before-item-mult` เก็บ 10 ชุด)
  2. ของในเกมทั้งหมดถูกคูณ: ที่สวม กระเป๋า ซื้อคืน คลัง ของบนพื้น · ตัวละครที่ออนไลน์ได้สเตตัสใหม่ทันที
  3. ของที่บันทึกใน DB ถูกคูณใน transaction เดียว: ตัวละครทุกตัว คลังทุกบัญชี รายการตลาดทุกสถานะ (รวมกล่องรับของ) และทำตัวค้นหาตามสเตตัสของตลาด (`market_listing_stats`) ใหม่
  4. ลง audit พร้อมจำนวนแถวที่คูณ เวลาที่ใช้ และชื่อไฟล์สำรอง
  - ของดรอปใหม่และการสุ่มที่ช่างตีเหล็ก: ช่วงค่าทั้งช่วงของสเตตัสนั้นถูกคูณ (tier อยู่ที่เดิม)
  - ของแนบในจดหมายเก็บเป็นสเปก (สุ่มตอนรับ) จึงได้ค่าใหม่เอง
- **กันคูณซ้ำ:** ไอเทมจำตัวคูณที่ใช้แล้วใน `Item.mulK` (`stat=ตัวคูณ;…` ไม่มี = ×1 ทั้งหมด) · ตอนโหลด (`upgradeItem`) ถ้าไม่ตรงกับที่ใช้อยู่ ค่าถูกคูณด้วย ใหม่ ÷ ที่ใช้แล้ว ครั้งเดียว · ของเสกจาก /admin ถือว่าอยู่ที่ตัวคูณปัจจุบันแล้ว
- **ปัดเศษ:** ตามทศนิยมของสเตตัส (% และฟื้น 1 ตำแหน่ง ที่เหลือจำนวนเต็ม อย่างน้อย 1) · ตั้งกลับ ×1 แล้วค่าอาจไม่กลับมาเท่าเดิมเป๊ะ (เจ้าของรับทราบ)
- **ป้าย tier:** คำนวณใหม่เทียบกับช่วงที่คูณแล้ว (ค่าและช่วงคูณเท่ากัน ป้ายจึงแทบไม่เปลี่ยน)
- **ระหว่างคนเล่นเยอะ:** เกมหยุดรอแค่ตอนสำรองและคูณ (DB ขนาดไม่กี่ MB คาดว่าไม่ถึง 1 วิ ในเทสต์ใช้ราว 20 ms) อาจกระตุกแวบเดียว ไม่มีใครหลุด

## ตัวคูณมอนธรรมดา (เจ้าของตกลง 2026-11-12)

- **มอนไหนบ้าง:** มอนทุกชนิดใน `monsters.ts` **ยกเว้น**บอสห้องบอส (`behavior: 'boss'`) เท่านั้น
  - ลูกน้องที่บอสเรียก (เจ้าของตกลงเพิ่ม 2026-11-13) โดนตัวคูณ**ตามชนิดของมัน** = ช่วงเลเวล (`levels[0]`) × รายชนิด เหมือนมอนในแมพ: หมาป่าที่หมีเรียกใช้ตัวคูณเดียวกับ `forest_wolf` ในแมพ
  - ชนิดที่มาเฉพาะตอนบอสเรียก (`summonOnly` เช่น `yeti_minion` Lv28) อยู่ในรายการให้ปรับรายชนิดด้วย และโดนตัวคูณช่วง Lv21–30
  - ลูกน้องยังไม่ให้รางวัล (EXP/ทอง/ของ) เหมือนเดิม ตัวคูณ EXP/ทองจึงไม่มีผลกับลูกน้อง
  - ซ้อนกับ HP/ATK × จำนวนกุญแจ (คูณตอนสร้างตัวใน `rawHp`/`rawAtk`) · บันทึกแล้ว `retune` ครอบคลุมลูกน้องที่เกิดอยู่ด้วย
- **แยก 2 ชั้น คูณซ้อนกัน:** ตามช่วงเลเวล (Lv1–10 / 11–20 / 21–30 / 31–40 / 41–50 เหมือน `TIER_BANDS`) × รายชนิด · ช่วงเลเวลดูจาก**เลเวลต่ำสุดของชนิดมอน** (`levels[0]`)
- **สเตตัส 9 ตัว ช่วง ×0.1–×10** (ไม่ตั้ง = ×1):
  - **HP, ATK, DEF:** คูณซ้อนกับที่แมพเพิ่มให้ (`monsterBoost`)
  - **วิ่งเร็ว**
  - **ตีเร็ว:** ×2 = คูลดาวน์โจมตีเหลือครึ่ง (ตีถี่ขึ้น 2 เท่า)
  - **EXP**
  - **ทอง:** คูณตอนดรอป
  - **ระยะ aggro:** มอนที่ไม่ตีก่อน (0) ยังเป็น 0 · aggro ที่แมพบังคับไม่ถูกคูณ
  - **ระยะโจมตี:** ระยะตีหรือระยะเริ่มยิง และระยะบินของกระสุน (`shot.range`) ของมอนยิงไกล
- **มีผลทันที:** ตอนบันทึก มอนที่เกิดอยู่แล้วทุกแมพ/CH/ห้องบอสคำนวณใหม่ (`Monster.retune` ใน `World.balanceChanged`) **HP คงสัดส่วนเดิม** · มอนที่เกิดใหม่ได้ค่าใหม่เอง · เบราว์เซอร์ได้ค่าผ่านข้อความ `balance` (HP สูงสุดมากับ snapshot อยู่แล้ว)
- **ที่เก็บ:** `monsters: { bands: { "1-10": { hp: 2 } }, types: { wild_boar: { atk: 1.5 } } }` ใน settings `balance` เฉพาะค่าที่ไม่ใช่ ×1 · ตรวจที่ server ใน `checkBalance` (ช่วงผิด สเตตัส/ช่วงเลเวลที่ไม่รู้จัก หรือบอส = 400) · audit แบบ `มอน หมูป่า HP ×1 → ×2` · ปุ่ม "คืนค่าในโค้ด" ลบตัวคูณมอนด้วย
- **หน้าจอ:** การ์ด "มอนธรรมดา (ตัวคูณ)" มี 2 ตาราง
  - ตารางแรก: 5 ช่วงเลเวล × 9 สเตตัส
  - ตารางที่สอง: มอนทุกชนิดเรียงตามเลเวล ใส่ตัวคูณรายตัวได้ ใต้แต่ละตัวมีแถว "ค่าจริง" (ค่าในโค้ด → หลังคูณทั้งสองชั้น) ที่เลเวลต่ำสุดของชนิดนั้น รวมที่แมพเพิ่มให้
  - ช่องที่ไม่ใช่ ×1 เป็นสีทอง

## กติกาที่ตกลงแล้ว

- **สิทธิ์:** สวิตช์ `balance` ใน `FEATURE_ROLES` (owner และ GM) owner ปิดของ GM ได้ในแท็บ "สิทธิ์" · ใครมีสวิตช์นี้ก็ทั้งดูและบันทึกได้ · ยกเว้นคอนเฟิร์มตัวคูณค่าสเตตัสบนไอเทม (สวิตช์ `itemStatMult` owner เท่านั้น)
- **ที่เก็บค่า:** settings key `balance` เก็บเฉพาะค่าที่ต่างจากโค้ด แบบเดียวกับ `cos_tuning`
  - ตาราง tier เก็บทั้งชุด 5 ค่าเมื่อมีค่าใดค่าหนึ่งต่าง
  - ตารางต่อสเตตัสเก็บใน `statTiers` (เรียงตาม `STAT_KEYS`) **การมีชื่อสเตตัสอยู่คือการตั้งเอง** จึงเก็บไว้แม้ตัวเลขเท่าค่าในโค้ด (ไม่งั้นตอนตารางกลางถูกแก้ สเตตัสนั้นจะไปตามตารางกลางเอง)
    - แต่ละส่วน (`weight` `width` `floor` `bossBoost`) ที่ไม่มี = ใช้ของตารางถัดไปตามลำดับข้างบน (หน้า /admin ตั้งครบ 4 ส่วนเสมอ ส่วนขาดมาได้จาก API เท่านั้น)
    - ตารางตามช่วงเลเวล: `bandTiers` (ทุกสเตตัส) และ `statTiers.<stat>.bands` (สเตตัส × ช่วง) key คือ `1-10` `11-20` `21-30` `31-40` `41-50` กติกาการเก็บเหมือนตารางต่อสเตตัส
  - DB ที่ไม่มีค่านี้ = ใช้ค่าในโค้ดทั้งหมด
- **ตรวจค่าที่ server:** server ตรวจทุกครั้ง (`checkBalance` ใน `src/shared/balance.ts`) ค่าผิดช่วงหรือไม่รู้จักได้ 400 · ค่าที่อ่านจาก DB ถูกตรวจแบบผ่อน ค่าที่โค้ดไม่ยอมรับแล้วถูกทิ้ง ที่เหลือใช้ได้
  - Lv1 และต่อเลเวล:
    - HP/MP 0–100,000 · ATK/DEF 0–10,000
    - คริ 0–100 · ดาเมจคริ 0–1,000 · ตีเร็ว/วิ่งเร็ว 0–300 · ฟื้น 0–1,000
  - ตัวคูณอาชีพ 0–10 · ดาเมจใส่บอส 0.1–10 · ตัวตัดฟื้น 0–5 · MP สกิลเพิ่มต่อเลเวล 0–20%
  - น้ำหนักโอกาส tier 0–1,000 (รวมกันต้อง > 0) · ความกว้าง 1–96% (รวม 100) · ค่าต่ำสุด 5–95% · บอสเพิ่ม tier 0–10 (ตารางกลางและตารางต่อสเตตัสใช้ช่วงเดียวกัน)
- **มีผลทันที:** ตอนบันทึก ทุกตัวละครที่อยู่ในเกม (ทุกแมพ/CH/ห้องบอส) จะได้สเตตัสใหม่ทันที
  - ป้าย tier ของของในตัว กระเป๋า ซื้อคืน คลัง และของที่วางบนพื้นถูกทำใหม่ทันที
  - เบราว์เซอร์ได้ข้อความ `balance` จึงเห็นตารางโอกาสของช่างตีเหล็กตรงกับ server (ค่านี้ส่งใน `welcome` ตอนเข้าเกมด้วย)
  - ไม่ต้องรีสตาร์ท server
- **บันทึกการแก้ไข:** ทุกครั้งที่บันทึกลง `admin_audit` (action `balance`) พร้อมรายการ "ค่าเดิม → ใหม่" · ปุ่ม "คืนค่าในโค้ด" ลบค่าทั้งหมด (ลง audit ด้วย)
- **บอส:** บอสยังใช้ 1.5 เพิ่มโอกาส rarity สูงตามโค้ดเสมอ แท็บนี้ปรับเฉพาะโอกาส tier ของบอส (แยกต่อสเตตัสได้)
- **โอกาส tier ไม่ย้ายช่วงค่า:** ช่วงค่าวางให้ค่าเฉลี่ยเท่าเดิมโดยคำนวณจากโอกาส**ในโค้ด**เสมอ (ตารางต่อสเตตัสก็เช่นกัน ใช้ความกว้าง/ค่าต่ำสุดของสเตตัสนั้นกับโอกาสในโค้ด)
  - เปลี่ยนโอกาสจึงมีผลกับของดรอปใหม่ (และการสุ่มที่ช่างตีเหล็ก) เท่านั้น
  - ช่วงค่าจะเลื่อนเฉพาะตอนแก้ความกว้างหรือค่าต่ำสุด

## ของที่ผู้เล่นมีอยู่แล้ว

- เปลี่ยนความกว้างหรือค่าต่ำสุดแล้ว **ค่าบนของไม่เปลี่ยน** มีแค่ป้าย tier และช่วง min–max ที่คำนวณใหม่ (เจ้าของรับทราบ)
  - การสุ่มค่าตัวเลขที่ช่างตีเหล็กใช้ tier ใหม่
- ไอเทมจำตารางที่ใช้คำนวณป้ายไว้ใน `Item.tierK` (`stampTier` ใน `items.ts`) ไม่มีค่า = ตารางในโค้ด
  - รูปแบบ: ส่วนของตารางกลาง (`กว้าง|ค่าต่ำสุด` หรือว่าง) ตามด้วย `;stat=กว้าง|ค่าต่ำสุด` เฉพาะสเตตัส**ที่อยู่บนไอเทมชิ้นนั้น**และป้ายต่างจากตารางกลาง เช่น `;moveSpeed=40,30,15,10,5|10`
  - แก้ตารางของสเตตัสหนึ่ง จึงทำป้ายใหม่เฉพาะของที่มีสเตตัสนั้น · ไม่ได้ตั้งตารางต่อสเตตัสเลย = รูปแบบเหมือนเดิม ของที่เซฟไว้ไม่ถูกแตะ
  - ส่วนแรกของ key คือตารางของช่วงเลเวลของไอเทม (ช่วงที่ไม่ได้ตั้ง = ตารางกลาง) แก้ตารางช่วง Lv31–40 จึงทำป้ายใหม่เฉพาะของเลเวล 31–40
  - `upgradeItem` ทำป้ายใหม่เมื่อ `tierK` ไม่ตรงกับตารางที่ใช้อยู่
  - ของที่ไม่ได้อยู่ในเกมตอนบันทึก (ตัวละครออฟไลน์ คลัง ตลาด) ได้ป้ายใหม่ตอนถูกอ่านครั้งถัดไป
  - คืนค่าในโค้ดแล้ว ป้ายกลับเป็นแบบเดิมทุกตัว
- ไม่แตะ `TIER_VERSION` เพราะตัวนั้นคุมการแปลงของเก่าก่อน v3 (ลดบรรทัดเสริมครึ่ง + เพิ่มคริล็อก) ซึ่งย้อนไม่ได้
