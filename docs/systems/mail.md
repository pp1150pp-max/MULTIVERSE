# กล่องจดหมาย (Mailbox)

สรุปสั้นอยู่ใน [CLAUDE.md](../../CLAUDE.md) · ผู้ดูแล/สิทธิ์: [accounts-and-admin.md](accounts-and-admin.md) · แบบเดียวกับกล่องรับของตลาด: [stash-and-market.md](stash-and-market.md)

โค้ด: กติกาและชนิดข้อมูล `src/shared/mail.ts` · server `server/mail.ts` (ผู้เล่น) + `server/admin-mail.ts` (แท็บ "จดหมาย" ใน `/admin`) · หน้าต่างในเกม `src/client/mail.ts` · ตาราง `mail_sends` / `mail_box` ใน `server/db.ts` (ตารางใหม่ล้วน ไม่แตะของเดิม)

## ผู้ส่งและผู้รับ

- ผู้ส่งคือ owner เท่านั้น (`FEATURE_ROLES.mail = ['owner']` ใน `src/shared/admin.ts` · เปิดให้ GM ภายหลังโดยเพิ่ม `'gm'`) ทุกการส่งและทุกการดึงกลับลง `admin_audit` (`mail`, `mailRecall`)
- เลือกผู้รับได้ 4 แบบ
  1. ตัวละครเดียว (พิมพ์ชื่อตัวละคร) — เฉพาะตัวนั้นอ่านและรับของได้
  2. บัญชีเดียว (พิมพ์ชื่อผู้ใช้) — ทุกตัวละครของบัญชีอ่านได้ รับของได้ **ครั้งเดียวต่อบัญชี** (ตัวไหนกดก่อนได้)
  3. ทุกตัวละคร — ตัวละครละ 1 สำเนา (บัญชีที่มี 3 ตัว ได้ 3 ฉบับ)
  4. ทุกบัญชี — บัญชีละ 1 สำเนา รับครั้งเดียว
- "ทุก…" = บัญชี/ตัวละครที่มีอยู่ตอนกดส่ง (ตัวที่สร้างทีหลังไม่ได้) · **Guest ไม่ได้รับจดหมาย** ไอคอนจดหมายถูกซ่อนสำหรับ Guest และ server ปฏิเสธ
- หัวข้อ ≤ 60 ตัวอักษร · เนื้อหา ≤ 1,000 ตัวอักษร (ตัดอักขระควบคุมออก เก็บขึ้นบรรทัดใหม่) · server ตรวจทุกช่อง

## ของแนบ

- แนบได้: ทอง, อุปกรณ์, ยา, หินช่างตีเหล็ก (ตัวเลือกเหมือนฟอร์มเสกของใน `/admin`) หรือไม่แนบเลยก็ได้
- เพดานต่อ 1 ฉบับ (ที่ `src/shared/admin.ts`): ทอง ≤ 1,000,000 G · ของ **รวมกันไม่เกิน 10 ชิ้น** (ยา/หินนับทีละขวด/ก้อน)
- **อุปกรณ์สุ่มตอนผู้เล่นกดรับ** ตามอาชีพของคนที่กดรับ · เลเวลไอเทมตามที่ admin กรอก ถ้าเว้นว่าง = เลเวลของคนกดรับ (ไม่ต่ำกว่าเลเวลขั้นต่ำของชนิดนั้น) · ไม่มีโหมดกำหนดสเตตัสเองในจดหมาย
  - **ชนิดที่เป็นของอาชีพเดียว** (เช่น off-hand ประจำอาชีพ) แนบได้เฉพาะจดหมายถึงตัวละครเดียวที่เป็นอาชีพนั้น (ส่งแบบบัญชี/ทุกคน server ตอบ 400) — เจ้าของเลือกแบบนี้ ไม่ให้ใครได้ของที่สวมไม่ได้
- ของแนบที่เก็บไว้ไม่ถูกตรวจเพดานซ้ำตอนรับ (ถ้าลดเพดานทีหลัง จดหมายเก่ายังรับได้) บรรทัดที่ชนิดไอเทมถูกลบไปแล้วจะถูกข้าม

## การรับของ (Claim)

- server เช็กก่อนว่ากระเป๋ามีที่ใส่ **ทุกอย่างที่แนบ** (จำลองบนสำเนากระเป๋า; ยา/หินเติมกองเดิมก่อน) ไม่พอ = ไม่ให้อะไรเลย (ทองด้วย) และบอกว่าต้องมีช่องว่างอย่างน้อยกี่ช่อง
- ให้ครั้งเดียว ไม่หาย: ทำใน transaction เดียวกับการเซฟตัวละคร โดย `UPDATE … WHERE claimed_at IS NULL AND ไม่ถูกดึงกลับ AND ยังไม่หมดอายุ` (`mailMarkClaimed`) ถ้าไม่สำเร็จ (กดซ้อน, สองตัวละครของบัญชีเดียวกัน, ถูกดึงกลับพอดี) ย้อนกระเป๋า/ทองกลับ ไม่ให้ซ้ำ
- ของทุกชิ้นได้ uid ใหม่ตอนรับ (ไม่ซ้ำกันข้ามสำเนา)
- ปุ่ม "รับทั้งหมด": รับทีละฉบับ (ฉบับไหนที่ไม่พอที่ข้ามไป ฉบับอื่นยังรับ) แต่ละฉบับ all-or-nothing

## การลบ

- ลบจดหมายที่ **ยังมีของแนบที่ยังไม่รับ ไม่ได้** · ลบได้เมื่ออ่านแล้ว และไม่มีของแนบหรือรับของแล้ว
- ปุ่ม "อ่านทั้งหมด" (เจ้าของตกลง 2026-11-13): ทำเครื่องหมายอ่านแล้วทุกฉบับ (call `mailReadAll`) ป้ายจำนวนหาย **ไม่รับของแนบ** ของยังรออยู่ · วางระหว่าง "รับทั้งหมด" กับ "ลบที่อ่านแล้วทั้งหมด"
- ปุ่ม "ลบที่อ่านแล้วทั้งหมด" ไม่ลบฉบับที่มีของแนบที่ยังไม่รับ

## หมดอายุ

- จดหมายหมดอายุ 30 วันหลังส่ง (`MAIL_DAYS`) ของแนบที่ยังไม่รับหายไปพร้อมจดหมาย (ซ่อนจากผู้เล่น รับไม่ได้) · ข้อมูลใน DB และประวัติ admin เก็บ 60 วัน (`MAIL_HISTORY_DAYS`) แล้วลบในรอบทำความสะอาดรายชั่วโมง

## แจ้งเตือน

- ออนไลน์ตอนจดหมายมา: ข้อความระบบในแชท + เสียง · ออฟไลน์: ตอนเข้าเกมขึ้น "มีจดหมายใหม่ X ฉบับ" (หน่วง 3 วิ เหมือนตลาด) · ไอคอนจดหมาย (อยู่ในตารางเมนูช่องที่แจ้งปัญหาเคยอยู่ ไม่อยู่ในแถวมุมขวาบนแล้ว) มีป้ายจำนวนที่ยังไม่อ่าน · ไอคอนตอนนี้เป็นรูปชั่วคราว (✉ บนป้ายเปล่า) รอเพื่อนวาดแล้วเปลี่ยนเป็น `badge('mail')` ใน `src/client/sysmenu.ts`
- ข้อความจาก server: `mailNote { unread, fresh }` · ตอบคำสั่งผู้เล่นด้วย `mail { req, … }` (คำสั่ง `mailList` `mailRead` `mailClaim` `mailDelete` `mailDeleteRead` จำกัด 1 ครั้ง/100 ms ต่อคน)

## ดึงกลับ และประวัติ (แท็บ "จดหมาย" ใน /admin)

- **ดึงกลับ**: ดึงเฉพาะสำเนาที่ยังไม่มีใครรับของ (สำเนาที่รับแล้วคงไว้) สำเนาที่ถูกดึงหายจากกล่องผู้เล่นและรับไม่ได้ · ดึงซ้ำเมื่อไม่เหลือสำเนาที่ดึงได้ = ปฏิเสธ
- ประวัติการส่ง: หัวข้อ ผู้รับ ผู้ส่ง เวลา ของแนบ และจำนวนสำเนา/อ่านแล้ว/รับของแล้ว/ดึงกลับ · "ดูผู้รับ" แสดงว่าใครอ่าน/รับแล้ว (สูงสุด 200 สำเนาแรก)
