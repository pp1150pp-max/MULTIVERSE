# เติมคริสตัลมิติผ่านพร้อมเพย์ (กึ่งมือ)

เจ้าของตกลง 2026-11-22 สำหรับ close beta · กติกาและการตรวจค่า: `src/shared/topup.ts` · server: `server/topup.ts`, `server/admin-topup.ts` · หน้าต่างในเกม: `src/client/cashShop.ts` (หน้าต่างแพ็กเกจ) · แท็บ admin: `src/admin/topup.ts` · เทสต์: `tests/topup.test.ts` · แคชช็อป: [cash-shop.md](cash-shop.md)

## ภาพรวม

- ไม่มีผู้ให้บริการชำระเงิน: ผู้เล่นโอนพร้อมเพย์เข้าบัญชีของเจ้าของเอง แล้วเจ้าของกดยืนยันใน /admin เมื่อ**เห็นยอดเข้าในแอปธนาคารจริง** · **ห้ามเชื่อสลิป** (ปลอมได้ง่าย)
- **อัตราแลกไม่ฝังในโค้ด**: ใช้แพ็กเกจในแท็บ /admin "แคชช็อป" (คริสตัล + โบนัส + ราคาบาท) เจ้าของยังไม่ตัดสินใจราคา (2026-11-22) · การเติมเปิด/ปิดแยกจาก "เปิดขาย" ของแคชช็อป

## ฝั่งผู้เล่น

- แคชช็อป → ปุ่ม + ข้างยอดคริสตัล → หน้าต่าง "เติมคริสตัลมิติ" → เลือกแพ็กเกจ → ถามยืนยัน (พร้อมข้อความแจ้ง) → server สร้างคำขอ
- **ยอดที่ต้องโอน = ราคาแพ็ก + เศษ 1–99 สตางค์** สุ่มจากที่ไม่ซ้ำกับคำขอที่ยังรอยืนยัน (ดัชนี unique ใน DB) เช่น 35.42 · ทั้ง 99 สตางค์ของราคานั้นถูกใช้หมด = "ลองใหม่ภายหลัง"
- หน้าต่างโชว์ **QR พร้อมเพย์แบบระบุยอด** (Thai QR / EMVCo สร้างใน `promptPayPayload` ไม่เรียกบริการภายนอก ตรงกับเทสต์ของแพ็กเกจ promptpay-qr · รูป QR วาดในเบราว์เซอร์ด้วย `qrcode-generator` (MIT) โหลดเฉพาะตอนเปิด QR) + ยอดตัวใหญ่ + ได้กี่คริสตัล + รอยืนยันถึงเมื่อไร + ปุ่ม "ยกเลิกคำขอ" (เตือนว่าถ้าโอนแล้วอย่ายกเลิก)
- ปิดหน้าต่างแล้วเปิดใหม่ / เข้าเกมใหม่ = เห็นคำขอเดิมและ QR เดิม (QR สร้างจากเลขพร้อมเพย์ปัจจุบัน: เจ้าของเปลี่ยนเลข = QR ของคำขอที่ค้างชี้เลขใหม่) · ทุกตัวละครของบัญชีเห็นตรงกัน
- ยืนยันแล้ว: คริสตัลเข้าทันที + ข้อความในแชท "เติมคริสตัลมิติสำเร็จ" · ปฏิเสธ/ย้อน: มีข้อความแจ้งเช่นกัน
- Guest เติมไม่ได้ · เติมผ่าน action `topupNew { crystals, bonus, baht }` (ต้องตรงกับแพ็กเกจที่ขายอยู่ตอนนี้ ไม่งั้น "แพ็กเกจนี้เปลี่ยนไปแล้ว") และ `topupCancel { id }` ตอบ `topupRes` · สถานะ `topup` (ใน `welcome` ด้วย) · 1 ครั้ง/2 วิ ต่อตัวละคร
- **ข้อความแจ้งผู้เล่น** (เจ้าของอนุมัติร่าง 2026-11-22 แก้ได้ใน /admin): สนับสนุนช่วง close beta · เพชรแลกคืนเป็นเงินไม่ได้ · ของที่ซื้อและคริสตัลที่เหลือหายตอนล้างข้อมูลก่อน open beta · open beta ได้คืนเท่าที่ได้รวมโบนัส · โอนให้ตรงทุกสตางค์ ไม่ต้องส่งสลิป

## กติกาคำขอ (เจ้าของเลือก 2026-11-22, ปรับได้ใน /admin)

- อายุคำขอ **24 ชม.** (1–168) · หมดอายุแล้วเศษสตางค์นั้นกลับไปใช้ได้ แต่เจ้าของ**ยังยืนยันได้** (เผื่อโอนช้า)
- คำขอรอยืนยันต่อบัญชี **1** (1–5) · คำขอใหม่ต่อวันต่อบัญชี **10** (1–100 กันกดสร้าง/ยกเลิกวนจนเศษสตางค์หมด)
- สถานะ: รอยืนยัน → ยืนยันแล้ว / ปฏิเสธ / หมดอายุ / ผู้เล่นยกเลิก · ยืนยันแล้ว → ย้อนแล้ว · หมดอายุ/ยกเลิก ยังยืนยันหรือปฏิเสธได้

## /admin แท็บ "เติมเงิน" (หมวดปรับเกม)

- **สิทธิ์**: `topup` ดูแท็บ (owner + GM, GM เห็นเลขพร้อมเพย์แค่ 4 ตัวท้าย) · `topupConfirm` ยืนยัน/ปฏิเสธ/ย้อน (owner) ปรับต่อ role ในแท็บ "สิทธิ์" · **ตั้งค่า (เลขพร้อมเพย์ เปิด/ปิด อายุ จำนวน ข้อความ) และสวิตช์คืนเพชร = owner เท่านั้นเสมอ ไม่มีสวิตช์**
- การ์ด "รอยืนยัน": คำขอรอยืนยัน + ที่หมดอายุ/ยกเลิกใน 3 วัน · บัญชี ตัวละคร แพ็ก **ยอดที่ต้องโอน (มีสตางค์)** สถานะ หมดอายุเมื่อไร · ปุ่มยืนยัน (ถามยืนยัน + เตือนห้ามเชื่อสลิป) / ปฏิเสธ · ป้าย "⚠ ยอดซ้ำ" ถ้ายอดเดียวกันมีมากกว่า 1 รายการที่ยังยืนยันได้ (แอปธนาคารแยกไม่ออกว่าใครโอน)
- การ์ด "ประวัติ" (300 รายการล่าสุด) + ยอดรวมที่ยืนยันแล้ว (รายการ บาทรวมสตางค์ คริสตัล) · ปุ่ม "ย้อน" ที่รายการยืนยันแล้ว
- **ย้อน**: เอาคริสตัล (รวมโบนัส) ออก · ถ้าผู้เล่นใช้ไปแล้วจนเหลือไม่พอ = ย้อนไม่ได้ บอกว่าเหลือเท่าไร (ไม่ให้ติดลบ · ยังไม่ได้ถามเจ้าของว่าอยากให้หักเท่าที่มีไหม)
- ทุกการกระทำทำใน transaction เดียว: เปลี่ยนสถานะด้วย `UPDATE … WHERE status IN (…)` ก่อน (กดซ้ำ/สองหน้าต่างพร้อมกัน = 409) แล้วค่อยเพิ่ม/ลดคริสตัล
- audit: `topup-settings` (เลขพร้อมเพย์แค่ 4 ตัวท้าย), `topup-confirm`, `topup-reject`, `topup-reverse`, `topup-refund-switch`, `topup-refund` (ระบบ ตอนคืนให้บัญชี)
- เลขพร้อมเพย์เก็บใน DB `settings` key `topup` (เฉพาะค่าที่ต่างจากโค้ด) **ไม่อยู่ใน repo ไม่ลง log/audit** · server ไม่ log payload QR
- API: `GET /api/admin/topup` · `POST /api/admin/topup/settings { cfg, base }` (409 ถ้าหน้าเก่า) · `POST /api/admin/topup/:id/confirm|reject|reverse` · `POST /api/admin/topup/refund { on }`

## สมุดบัญชีการเติม + คืนเพชร open beta

- ตาราง `topups` = สมุดบัญชี (ทุกคำขอ ยืนยันเมื่อไรโดยใคร) และ `topup_refunds` (บัญชีที่ได้คืนแล้ว) **ไม่ล้างตอนล้างข้อมูลเกม** ไม่มี foreign key (ลบบัญชีแล้วแถวยังอยู่ มีชื่อผู้ใช้/ตัวละครตอนขอ) · วิธีล้าง: [server-ops.md](server-ops.md) "ล้างข้อมูลเกม"
- **คืนเพชร close beta** (เจ้าของเลือก: คืนเท่าเพชรที่ได้รวมโบนัส): owner กดเปิดในการ์ด "คืนเพชร close beta" **หลังล้างข้อมูล** → เก็บเวลาที่เปิด (settings `topup_refund`) → แต่ละบัญชีได้คริสตัลคืนตอนเข้าโลกครั้งแรกหลังจากนั้น ครั้งเดียว (`topup_refunds` primary key) = ผลรวมคริสตัล+โบนัสของรายการที่**ยืนยันก่อนเวลาที่เปิด**และยังไม่ถูกย้อน · มีข้อความในแชท · ลง audit `topup-refund`
- **ต้องปิดการเติมก่อน** ถึงจะเปิดคืนเพชรได้ (409) กันรายการที่ยืนยันหลังล้างข้อมูลได้ทั้งเพชรตอนนั้นและเพชรคืน · ห้ามยืนยันรายการระหว่างล้างข้อมูลกับเปิดคืนเพชร
- ปิดสวิตช์ได้ (บัญชีที่ได้แล้วไม่ถูกหัก) เปิดใหม่ = เวลาตัดใหม่ แต่บัญชีที่ได้แล้วไม่ได้ซ้ำ

## ยังไม่ได้ทำ / ต้องเจ้าของทำเอง

- ลองสแกน QR จริงด้วยแอปธนาคารของเจ้าของ (เทสต์ตรวจ payload + CRC กับค่าอ้างอิงแล้ว แต่สแกนจริงยืนยันได้ที่แอปเท่านั้น)
- ใส่แพ็กเกจและราคาในแท็บแคชช็อป (ยังไม่มีค่าตัวอย่าง)
- หน้า `privacy.html` เพิ่มหัวข้อการเติมคริสตัลแล้ว (ปรับปรุง 22 พ.ย. 2569) เจ้าของตรวจข้อความ · ข้อ 5 ยังบอกว่าลบบัญชี = ลบทั้งหมด ขัดกับ "เก็บบันทึกการเติมแม้ลบบัญชี" เจ้าของต้องเลือก
