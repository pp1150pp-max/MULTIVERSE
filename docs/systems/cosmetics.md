  - **ปรับตำแหน่งเป็นแกน X/Y/Z (เจ้าของตกลง 2026-11-11)** X = ซ้าย/ขวาของตัวละคร (+ = ขวา) · Y = ขึ้น/ลง · Z = หน้า(+)/หลัง หมุนตามทิศที่ตัวละครหัน (`COS_AXES` ใน `cosTuning.ts`)
    - แกนอ่านจากค่าเดิมโดยไม่เปลี่ยนชื่อ จึงใช้เซฟเก่าได้ตรง ๆ ตำแหน่งไม่กระโดด: ปีก X=`shift` · Y ตอนยืน=`backStand` · Y ตอนขี่=`backSeat` (ยังแยก 2 ค่า) · Z=−`back` / สัตว์ขี่ X=`shift` Y=`seat` Z=`z` (ใหม่ ค่าเริ่ม 0) / สัตว์เลี้ยง X=−`side` Y=`float` Z=−`back` / ออร่า X=`shift` · **ข้อควรรู้:** ค่าหลัก X ของ ปีก/สัตว์ขี่/ออร่า ยังเป็น "ซ้าย/ขวาบนจอ" แบบเดิม (กลับด้านเองตามภาพตอนหันซ้าย) ไม่ใช่หมุนตามตัวเพื่อให้เซฟเก่าไม่ขยับ ส่วนปรับของแต่ละมุมเป็นแกนของตัวละครจริง
    - **ซ่อนตามชนิด:** ออร่ามีแต่ X · สัตว์เลี้ยงที่เดินพื้น (`fly` ปิด) ไม่มี Y
    - **ซ่อนตามมุม:** เลือกทุกมุม (ค่าหลัก) หรือ 1 ใน **8 ทิศ** ด้วยลูกศร (หน้า · เฉียงหน้าขวา · ขวา · เฉียงหลังขวา · หลัง · เฉียงหลังซ้าย · ซ้าย · เฉียงหน้าซ้าย) หน้า/หลังตรงซ่อน Z · ซ้าย/ขวาซ่อน X · ทิศเฉียงแสดงครบ X/Y/Z · เกมก็ไม่ใช้แกนที่ซ่อนในทิศนั้น "ซ้าย/ขวา" คือด้านของจอที่ตัวละครหันไปหา
    - **ค่าแยกตามทิศ (เจ้าของตกลง 2026-11-11 หลังเริ่มแยกแค่ 3 กลุ่มแล้วทับกัน):** "ค่าหลัก" ต่อแกน (ใช้ทุกทิศ) + "ส่วนปรับ" ของแต่ละทิศแยกกันครบ 8 ทิศ เก็บเป็นช่อง `d<x|y|z>_at_<ทิศ>` (`front` `frontRight` `right` `backRight` `back` `backLeft` `left` `frontLeft` ค่าเริ่ม 0) บวกเข้าค่าหลักเฉพาะทิศนั้น · ส่วนปรับเป็นแกนของตัวละคร (ขวา/ขึ้น/หน้า) หมุนตามที่หัน
    - **เซฟเก่าที่เคยเก็บเป็น 3 กลุ่ม** (`d<x|y|z>_front/side/back`) แปลงตอนอ่านโดย `checkCosTuning`: front → หน้า+เฉียงหน้าซ้าย+เฉียงหน้าขวา · side → ซ้าย+ขวา · back → หลัง+เฉียงหลังซ้าย+เฉียงหลังขวา (ค่าเดียวกันกับที่เคยใช้ ตำแหน่งบนจอไม่กระโดด · ทิศที่เซฟเองแล้วชนะค่าเก่า) เขียนกลับเป็นรูปแบบใหม่ตอนบันทึกครั้งถัดไป
  - **ปีกภาพข้างเดียวแยกค่าต่อทิศ (เจ้าของตกลง 2026-11-23 หลังรายงาน "บันทึกทิศหน้าแล้วทิศอื่นเปลี่ยนด้วย")** สาเหตุเดิม: ตอนเลือกทิศ สไลเดอร์ปีกข้างเดียวยังเป็นค่าเดียวที่ใช้ทุกทิศ และปุ่มบันทึกทิศไม่ได้เซฟค่าเหล่านั้น
    - ขนาด `oneSize` · ระยะวาดหลังตัว/ทับหลัง `oneDepth` (ครบ 8 ทิศ) · มุมเอียง `oneTilt` · ปีกข้างไกลแคบลง `oneSqueeze` (เฉพาะ 4 ทิศเฉียง เพราะทิศอื่นไม่ใช้) มีส่วนปรับต่อทิศ `<ค่า>_at_<ทิศ>` (ค่าในโค้ด 0) บวกเข้าค่าหลัก เกมใช้ ค่าหลัก + ส่วนปรับ แล้วจำกัดไม่เกินช่วงของค่าหลัก (`valueAtDir`, `WING_ONE_DIR_FIELDS` ใน `cosTuning.ts`) · ช่วงส่วนปรับ = ±ความกว้างช่วงของค่าหลัก · เซฟเก่าไม่มีช่องเหล่านี้ = 0 ทุกทิศ หน้าตาเหมือนเดิม
    - ซ้าย/ขวาแยกกันครบ 8 ทิศ (เจ้าของเลือก เหมือนส่วนปรับ X/Y/Z) · ความสูงต่อทิศใช้ "Y ส่วนปรับทิศ" เดิม (ใช้ทั้งยืนและขี่) ไม่มีส่วนปรับ `oneBack`/`oneBackSeat` แยก

## ลูกแก้วตีบวกเป็นของแต่งตัว (เจ้าของตกลง 2026-11-13)

- ช่องของแต่งตัวใหม่ **"ลูกแก้วตีบวก"** (`orb`, อยู่ท้าย `COS_SLOTS` เพราะลำดับช่องอื่นเป็นส่วนของรหัส snapshot) · สวมแล้ว**เปลี่ยนแค่หน้าตา**ลูกแก้วของตัวละครนั้น (ชุดสี รูปทรง ขนาด ความเร็ว ฯลฯ ครบชุด `OrbLook`) ทุกคนเห็น · ลูกแก้วยังมาจากของที่สวม +7 ขึ้นไปตามกติกาเดิม ([items-and-forge.md](items-and-forge.md)) ไม่มีของ +7 = ไม่เห็นอะไร (รวมตอนลองสวม) · คนที่ไม่สวมใช้หน้าตาลูกแก้วของทั้งเซิร์ฟ
- กติกาเหมือนของแต่งตัวอื่นทุกข้อ: บัญชีต้องมี (admin ให้ในหน้าบัญชี) · ซ่อน/แสดง ราคาคริสตัลมิติ (ยังไม่ขาย) · Guest ไม่ได้ · ยึดคืนแล้วถอดเอง · ในหน้าต่าง "แต่งตัว" มีหมวด "ลูกแก้วตีบวก" (ภาพการ์ด = ลูกแก้ว 3 ลูกสีตามชุดสี/รูปทรงของชิ้นนั้น)
- **ไม่ได้อยู่ในโค้ด**: สร้างใน /admin ระหว่างที่ server รัน เก็บในตาราง `settings` key `orb_items` = `{ next, items: [{ id: 'orb_<n>', n, name, look }] }` ไม่มีแถว = ไม่มีลูกแก้วในร้าน (DB เก่าใช้ได้เลย) · `src/shared/orbItems.ts` (`registerOrbItems` ใส่เข้ารายการของแต่งตัว `COSMETICS` · server ทำตอนเปิด DB ก่อนอ่านของที่มี/สวม/ซ่อน) · รหัส snapshot = 1000 + n · **id/รหัสไม่ถูกใช้ซ้ำ** (`next` ไม่ลดลงแม้ลบชิ้นล่าสุด) · สูงสุด 200 ชิ้น · ชื่อ 1–30 ตัวอักษร
- ผู้เล่นได้รายการตอนเข้าเกม (`welcome.orbItems`) และทุกคนที่ออนไลน์ได้ทันทีเมื่อเปลี่ยน (`{ t: 'orbItems', items }`) · ไม่ส่งราคา
- **แท็บ "ลูกแก้วตีบวก"** (แท่นทดลองเดิม) หัวข้อ "ลูกแก้วในร้านค้า":
  - **"➕ เพิ่มในร้านค้า"** (สวิตช์ `orbShopAdd` = owner + GM) ถามชื่อ แล้วสร้างชิ้นใหม่จากหน้าตาที่ตั้งอยู่ **เริ่มแบบซ่อน ไม่มีราคา** (ตั้งซ่อนก่อนส่งรายการให้ผู้เล่น ไม่โผล่แม้ชั่วขณะ) · "ต่างสี/ต่างทรงรายลูก" จากปุ่มสุ่มไม่ถูกบันทึก
  - แท็บ "หน้าตา" ช่อง **"กำลังแก้"** เลือกชิ้นในร้านมาแก้ในแท่น (โหลดหน้าตาของชิ้นนั้น) → **"💾 บันทึกที่แก้"** ติ๊กค่าที่จะบันทึกทับชิ้นนั้น (สวิตช์ `cosManageEdit` = owner) คนที่สวมอยู่เห็นแบบใหม่ทันที
- **แท็บ "จัดการของแต่งตัว"** หัวข้อ "ลูกแก้วตีบวก" จัดการเหมือนชนิดอื่น: ซ่อน/แสดง ราคา · คอลัมน์ค่าหน้าตา เลือก "ค่าที่แก้" ได้ทุกค่าของ `OrbLook` (ชุดสี/รูปทรงเป็นช่องเลือก แสงนุ่มเป็นติ๊ก ตัวเลขช่วงเดียวกับสไลเดอร์ `ORB_LOOK_RANGES`) + บวก/ลบทุกชิ้นที่ติ๊ก · แก้ชื่อในช่อง · ปุ่ม "เปิดในแท่นทดลอง" · ปุ่ม **"ลบ"** (ถามยืนยัน ลบทันที) ได้**เฉพาะชิ้นที่ไม่มีบัญชีไหนมี** (มี = 409 ให้ยึดคืนหรือซ่อนแทน) · แก้ชื่อ/หน้าตา/ลบ ใช้ `cosManageEdit` (owner) บันทึกพร้อมปุ่ม "บันทึก" เดิม
- API: `GET /api/admin/orb-items` (`orbPreview`) คืน `{ orbs, canAdd, canEdit }` · `POST /api/admin/orb-items` `{ add: { name, look } }` (`orbShopAdd`) / `{ edit: { id: { name?, look? } }, base }` / `{ remove: id }` (`cosManageEdit`) · ตรวจแบบเข้ม (`checkOrbItems`, `checkOrbName`, `checkOrbLook`) · `GET /api/admin/cos-shop` มี `orbs` และ `orbOwners` (จำนวนบัญชีที่มีแต่ละชิ้น) · audit action `orb-items` เช่น `เพิ่ม orb_1 "ลูกแก้วไฟ"`, `orb_1: ชื่อ "ก" → "ข", scale 0.8 → 1`, `ลบ orb_2 "…"`

## เอฟเฟกต์เลเวลอัปเป็นของแต่งตัว (เจ้าของตกลง 2026-11-25)

- ช่องของแต่งตัวใหม่ **"เอฟเฟกต์เลเวลอัป"** (`levelup`, ต่อท้าย `COS_SLOTS` หลังลูกแก้ว รหัส snapshot = 6×16+n = 97–102 ช่องอื่นไม่เปลี่ยน) สวมได้ทีละ 1 แบบ · ไม่มีฟิลด์ใหม่ในเซฟ (`CharacterData.cosmetics` เดิม)
- **6 แบบ** วาดด้วยโค้ดทั้งหมด ไม่มีไฟล์ภาพ (`src/client/levelUpFx.ts`, `LEVELUP_STYLE`) ทุกแบบมี "LEVEL UP !" ในตัวหนังสือ/ลวดลายของแบบนั้น:
  - `levelup_cyan` **เลเวลอัป: วงเวทมิติ** — แบบ #485 (วงเวทหมุน เส้นแสง ประกาย ลูกศรเชฟรอนเหนือหัว)
  - `levelup_fire` **เลเวลอัป: พายุเพลิง** — วงเปลวไฟบนพื้น เปลวไฟ 3 แขนหมุนเป็นเกลียวขึ้นรอบตัว ถ่านไฟลอยแกว่ง ตัวหนังสือมีเปลวไฟเลียด้านบน
  - `levelup_thunder` **เลเวลอัป: สายฟ้าฟาด** — สายฟ้าผ่าลงหลายครั้ง (ครั้งแรกลงที่ตัว) มีแสงวาบ รอยแตกบนพื้นสว่างทุกครั้งที่ผ่า ประกายไฟฟ้ากระเด็น ตัวหนังสือกระแทกเข้าแล้วกะพริบ
  - `levelup_leaf` **เลเวลอัป: พายุใบไม้** — วงลมซ้อนกันลอยขึ้นเป็นกรวย ใบไม้หมุนเกลียวขึ้นและปลิวออก ตัวหนังสือแกว่งเบา ๆ
  - `levelup_star` **เลเวลอัป: ดาวตก** — วงกลุ่มดาวบนพื้น ดาวตกพุ่งเฉียงลงหาตัว (7 ดวง) ระเบิดประกายตอนตก ดาวกะพริบรอบตัว
  - `levelup_shadow` **เลเวลอัป: เงารัตติกาล** — แอ่งเงามืดบนพื้นกับวังวนหมุน ควันม่วงดำหมุนเข้าแล้วลอยขึ้น ตัวหนังสือโผล่จากควัน
- **ไม่ได้สวม = เสาแสงสีทองแบบเดิม** (ฟรี) และตัวหนังสือลอยแบบเดิม · สวมแบบที่เปิดตัวหนังสือ = ไม่มีตัวหนังสือลอยซ้ำ (`Effects.drewLevelUpTitle`)
- **คนอื่นเห็นแบบที่คนเลเวลอัปสวม** (จาก snapshot ของตัวนั้น) ตามเมนู "กราฟิก" ของผู้เล่นที่ดู: คุณภาพ "ปิด" = เหลือตัวหนังสือ · "ต่ำ/กลาง" = อนุภาคลดตาม · ของคนอื่น "ไม่แสดง" = เห็นแค่ตัวหนังสือ, "ครึ่งเดียว" = อนุภาคครึ่งเดียว · จอสัมผัส อนุภาคครึ่งเดียว · "วงบนพื้น" และ "ส่วนเด่น" หายเมื่อคุณภาพปิดหรือของคนอื่นไม่แสดง

- **ค่าหน้าตารายแบบ** เก็บใน `cos_tuning` เหมือนชิ้นอื่น (`COS_TUNE_FIELDS.levelup`): สีหลัก `color1` สีรอง `color2` (ตัวเลข 0xRRGGBB ชนิด `color`) · ขนาด `size` (0.3–3, โค้ด 1) · เวลา `sec` (0.5–6 วิ, โค้ด 2.2) · สวิตช์ วงบนพื้น `ground` อนุภาค `sparks` ส่วนเด่นของแบบ `main` (ลูกศร/เปลวไฟ/สายฟ้า/ลมใบไม้/ดาวตก/ควันวน) ตัวหนังสือ `text` · สีในโค้ดของแต่ละแบบ = สีในรายการ (`color`/`color2` ใน `cosmetics.ts`)
  - แท่นทดลอง แท็บย่อย **"เอฟเฟกต์เลเวลอัป"**: เลือกแบบ ปรับค่า (ไม่มีลูกศรทิศ/ตำแหน่ง) ปุ่ม **▶ ดูตัวอย่าง** เล่นบนตัวละครด้วยค่าที่ยังไม่บันทึก + ติ๊ก "เล่นซ้ำเรื่อย ๆ" · บันทึกด้วยปุ่มบันทึกเดิม (`cosLook` owner)
  - แท็บ "จัดการของแต่งตัว" มีหัวข้อเอฟเฟกต์เลเวลอัป: ซ่อน/แสดง ราคา และค่าหน้าตา (สีเป็นช่องเลือกสี บวก/ลบทุกชิ้นที่ติ๊กใช้กับตัวเลขเท่านั้น)
  - audit แสดงสีเป็น `#rrggbb`

## เอฟเฟกต์แดชเป็นของแต่งตัว (เจ้าของตกลง 2026-11-26)

- ช่องของแต่งตัวใหม่ **"เอฟเฟกต์แดช"** (`dash`, ต่อท้าย `COS_SLOTS` หลังเลเวลอัป รหัส snapshot = 7×16+n = 113–118 ช่องอื่นไม่เปลี่ยน) สวมได้ทีละ 1 แบบ · ไม่มีฟิลด์ใหม่ในเซฟ (`CharacterData.cosmetics` เดิม เซฟเก่าไม่มีช่องนี้ = ไม่ได้สวม)
- **ใช้กับปุ่มแดช (Space) ของทุกอาชีพเท่านั้น ไม่รวมสกิลที่พุ่งตัว** (ชาร์จ ท่าพุ่งของนักดาบ ถอยหลังของมือปืน ฯลฯ ยังเป็นแบบเดิม) · จับจากสัญญาณที่ Sim ส่งตอนกดแดช (`quarksCue(…, 'dash', มุม)` → `burst` มี `by` + `'dash'`) ไม่ต้องแก้ server
- **6 แบบ** วาดด้วยโค้ดทั้งหมด ไม่มีไฟล์ภาพ (`src/client/dashFx.ts`, `DASH_STYLE` ใช้ภาพพื้นฐานร่วมกับ `levelUpFx.ts`) ทุกแบบมี 4 ส่วน: วงแหวนตั้งขวางทางที่จุดเริ่ม/จุดปลาย (+ วงบนพื้น) · ทางที่พุ่ง · เงาตัวละครตามหลัง (สำเนาภาพตัวละครเฟรมนั้น จางลง) · อนุภาค
  - `dash_wind` **แดช: ลมฟ้า** — แบบในภาพของเจ้าของ: วงแหวนฟ้าขาวเรืองแสงสองปลาย เส้นความเร็วยาวเรืองแสง เงาตัวละครสีฟ้าจาง
  - `dash_fire` **แดช: เพลิง** — วงไฟสองปลาย ทางไฟไหม้บนพื้นมีเปลวไฟลุกขึ้น ถ่านไฟลอย
  - `dash_thunder` **แดช: สายฟ้า** — แสงวาบสองปลาย สายฟ้าหยักตามทาง 3 เส้นสลับรูปกะพริบ ประกายไฟฟ้ากระเด็น รอยแตกบนพื้น
  - `dash_leaf` **แดช: ใบไม้** — วงลมหมุนสองปลาย เส้นลม ใบไม้ปลิวตามทางแล้วร่วง
  - `dash_star` **แดช: ดาว** — วงกลุ่มดาวสองปลาย หางดาวหางสีทอง ดาวกะพริบตามทาง ดาวใหญ่แตกที่จุดปลาย
  - `dash_shadow` **แดช: เงา** — วังวนมืดสองปลาย ควันม่วงดำตามทาง เงาตัวละครสีมืดถี่กว่าแบบอื่น
- **จุดปลาย** ตามตำแหน่งตัวละครจริง 0.4 วิแรก (ชนกำแพง = จบตรงที่หยุด ไม่เกิน 4.8 หน่วยของแดช)
- **ไม่ได้สวม = แดชแบบเดิมทุกอย่าง** · สวมอยู่ = เอฟเฟกต์ three.quarks ของแดชเดิมไม่เล่น (ควันจาง ๆ ระหว่างพุ่งของเดิมยังมี เพราะใช้ร่วมกับสกิลที่พุ่งตัว)
- **คนอื่นเห็นแบบที่คนแดชสวม** (จาก snapshot ของตัวนั้น) ตามเมนู "กราฟิก" ของผู้เล่นที่ดู: คุณภาพ "ปิด" หรือของคนอื่น "ไม่แสดง" = เห็นแดชแบบเดิม · "ต่ำ/กลาง" = อนุภาคลดตาม · ของคนอื่น "ครึ่งเดียว" = อนุภาคครึ่งเดียว · จอสัมผัส อนุภาคครึ่งเดียว

- **ค่าหน้าตารายแบบ** เก็บใน `cos_tuning` เหมือนชิ้นอื่น (`COS_TUNE_FIELDS.dash`): สีหลัก `color1` สีรอง `color2` · ขนาด `size` (0.3–3, โค้ด 1) · เวลา `sec` (0.2–1.5 วิ, โค้ด 0.55 ตัวพุ่งจริง 0.18 วิ ที่เหลือคือจาง) · สวิตช์ วงสองปลาย `ends` ทางที่พุ่ง `trail` เงาตัวละคร `ghosts` อนุภาค `sparks` · สีในโค้ด = สีในรายการ (`color`/`color2` ใน `cosmetics.ts`)

## กระเป๋าแฟชั่น (เจ้าของตกลง 2026-11-18)

- หน้าต่างกระเป๋ามีแท็บ **"กระเป๋า" / "ประเภทใช้งาน" / "แฟชั่น"** ชิดซ้ายแถวเดียวกับแถบเรียงของ (หน้าแฟชั่นซ่อนแถบเรียงของ · แท็บประเภทใช้งานเพิ่ม 2026-11-23 ดู [items-and-forge.md](items-and-forge.md)) · โค้ด `src/client/fashionBag.ts`
- **ใส่เฉพาะของแต่งตัว** ครบทุกชนิด (ปีก สัตว์ขี่ สัตว์เลี้ยง ออร่า กรอบชื่อ/ฟองแชท ลูกแก้วตีบวก เอฟเฟกต์เลเวลอัป เอฟเฟกต์แดช) · หิน/ใบคูณ/โทรโข่งจากแคชช็อปยังอยู่กระเป๋าปกติเหมือนเดิม
- ใช้ 30 ช่องที่วาดไว้ของกระเป๋า เฉพาะชิ้นที่บัญชีมี (ไม่โชว์ชิ้นที่ยังไม่มี) เรียงตามชนิด (`COS_SLOTS`) เกิน 30 ชิ้น = ลูกศรเปลี่ยนหน้า (ไม่มีปุ่มกรองชนิด) · ชิ้นที่ซ่อนใน /admin ใช้กติกาเดียวกับแท็บ "ของฉัน" (เห็นเฉพาะตอนสวมอยู่)
- ครึ่งบนของหน้าต่าง (ช่องสวมใส่) เปลี่ยนเป็นแถบของแต่งตัวที่สวมอยู่ 6 ช่องในภาพ + ช่องเอฟเฟกต์เลเวลอัป (ขวาของหัวข้อ) และเอฟเฟกต์แดช (ซ้ายของหัวข้อ) ในกรอบเล็กวาดด้วยโค้ด คลิก = ถอด
- คลิกของในกระเป๋าแฟชั่น = สวม/ถอดทันที (ชิ้นที่สวมอยู่มีกรอบทอง + ✓) ชี้เมาส์ = ชื่อ/คำอธิบาย · มือถือแตะ = แผงรายละเอียดมีปุ่มสวม/ถอด · คลิกขวาไม่ทำอะไร (ทิ้ง/ขายไม่ได้)
- ใช้ action `cosWear` เดิม server ตรวจใน `wearCosmetic` เหมือนเดิม ไม่มี action ใหม่ ไม่แก้ server
- เปิดร้าน/คลัง/ตลาด/เทรด/ช่างตีเหล็ก = กลับหน้ากระเป๋าปกติ แท็บแฟชั่นกดไม่ได้จนกว่าจะปิด · ปิดหน้าต่างกระเป๋า = เปิดครั้งหน้าเป็นกระเป๋าปกติ · Guest ขึ้นข้อความว่ารับของแต่งตัวไม่ได้
- **/admin: ไม่มีค่าใหม่** (เจ้าของเลือก 2026-11-18) ใช้การซ่อนรายชิ้นในแท็บ "จัดการของแต่งตัว" ที่มีอยู่
- หน้าแฟชั่นมีภาพหน้าต่างของตัวเอง `public/assets/sprites/ui/inventory_fashion.png` (เจ้าของเจนใน GPT 2026-11-18 สไตล์กระดาษ, prompt ใน `art_templates/ui/PROMPTS.md`, ตัดสีม่วงแดงออกแล้วย่อเท่า `inventory.png`): กรอบ 6 ช่อง + ป้ายชื่อ + 30 ช่อง ตำแหน่งวัดจากภาพ (ค่าคงที่ใน `fashionBag.ts` และ CSS `#inventory.fashion`) · หน้ากระเป๋าปกติยังเป็นภาพ pixel-art เดิม
- คำอธิบายสัตว์ขี่แสดงบรรทัด "ความเร็วเคลื่อนที่ +30% (ตอนขี่)" ต่อท้ายทุกที่ที่มีคำอธิบาย (แคชช็อป กระเป๋าแฟชั่น หน้าต่างของแต่งตัว) คิดจาก `MOUNT_SPEED` ในโค้ด ไม่มีค่าใน /admin (เจ้าของ 2026-11-22)

## ลองสวมได้เฉพาะในเมือง (เจ้าของ 2026-11-25)

- ปุ่ม "ลองสวม" ในแคชช็อปและหน้าต่างแต่งตัว กดได้เฉพาะตอนตัวละครอยู่ในเมือง/safe zone (`inSafeArea`) นอกเมืองขึ้น "ลองสวมได้เฉพาะในเมือง" ในช่องข้อความ
- ลองค้างไว้แล้วเดินออกนอกเมือง = ถอดที่ลองให้เอง (ทั้งหน้าต่างแต่งตัวและแคชช็อป ตรวจทุกเฟรมใน `cosmetics.ts` → `cosLook.tryOnBlocked`)
- ฝั่งเบราว์เซอร์เท่านั้น (ของที่ลองเห็นแค่ตัวเอง server ไม่รู้)
- สวิตช์ `tryOnTownOnly` แท็บปรับสมดุล หัวข้อ "ร้านพ่อค้าและแชท" (ค่าในโค้ด เปิด, ปิด = ลองได้ทุกที่ตามเดิม, ลง audit)
