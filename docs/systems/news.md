# มีอะไรใหม่ (ประกาศอัปเดต)

สรุปสั้นอยู่ใน [CLAUDE.md](../../CLAUDE.md) · ผู้ดูแล/สิทธิ์: [accounts-and-admin.md](accounts-and-admin.md) · จัดปุ่มเมนู: [world-and-ui.md](world-and-ui.md) หัวข้อ "จัดเมนูเกม" · ขึ้น server: [server-ops.md](server-ops.md)

เจ้าของตกลง 2026-11-22 · ให้ผู้เล่นรู้ว่าแต่ละอัปเดตมีอะไรใหม่ ข้อความเก็บ **ในตาราง DB `news`** (ไม่ใช่ไฟล์ใน repo เพราะ main ล็อก) จึงลงได้โดยไม่ต้องเปิด PR

โค้ด: กติกาและตัวตรวจค่า `src/shared/news.ts` · ตาราง/เมธอด `news*` ใน `server/db.ts` · แท็บ /admin `server/admin-news.ts` + `src/admin/news.ts` · หน้าต่างในเกม `src/client/news.ts` · สคริปต์ลงจาก command line `server/add-news.ts` (`npm run add-news`) · เทสต์ `tests/news.test.ts`, `tests/news-server.test.ts`

## ในเกม

- ปุ่ม **"มีอะไรใหม่"** อยู่ในหน้าต่างเมนู (ถัดจาก "วิธีเล่น") ย้ายไปแถวมุมขวาบนได้ที่ /admin → จัดเมนูเกม (id `news`) · **Guest เห็นและเปิดได้**
- เปิดแล้วเป็นหน้าต่างใหญ่ แสดง **5 ประกาศล่าสุดที่ไม่ได้ซ่อน** (ใหม่สุดบน) แต่ละอัน: หัวข้อ · วันเวลา (เวลาไทย ปี พ.ศ.) · รายการสั้น ๆ · ประกาศที่เก่ากว่า 5 อันล่าสุดไม่โชว์ (ยังอยู่ใน /admin)
- **จุดแดง** บนปุ่ม (และบนปุ่มเมนูถ้าปุ่มอยู่ในหน้าต่างเมนู) เมื่อมีประกาศที่ id ใหม่กว่าที่เบราว์เซอร์นี้เคยเปิดดู · เก็บใน localStorage `multiverse-news-seen` (ต่อเบราว์เซอร์ ไม่ใช่ต่อบัญชี) · เปิดหน้าต่าง = ถือว่าเห็นทั้งหมด · แก้ข้อความประกาศเดิมไม่ทำให้จุดแดงกลับมา
- **ไม่เด้งหน้าต่างเอง** ยกเว้นสวิตช์ "เด้งเอง" เปิด: ครั้งเดียวตอนเข้าเกม (ข้อความ `news` ข้อความแรกของหน้านั้น) ถ้ามีประกาศที่ยังไม่เปิดดู · ประกาศที่มาตอนกำลังเล่นแค่ขึ้นจุดแดงทันที ไม่เด้ง
- server ส่ง `{ t: 'news', v: NewsView }` ให้ทุกคน (Guest ด้วย) หลังเข้าเกม ~3 วิ และทุกครั้งที่ประกาศ/สวิตช์เปลี่ยน

## ปุ่มใน "จัดเมนูเกม" ที่เจ้าของเคยจัดไว้แล้ว

เลย์เอาต์ที่บันทึกก่อนมีปุ่มนี้จะไม่มี `news` ในลิสต์ → ปุ่มจะไม่โผล่ จึงมีกติกา: **ถ้า `news` ไม่อยู่ทั้งหน้าต่างเมนูและแถวมุมขวาบน ระบบเติมให้ในหน้าต่างเมนู ก่อนปุ่ม "ตั้งค่า"** (`ADDED_LATER` ใน `src/shared/menuLayout.ts`) ย้ายไปแถวบนได้ตามปกติ · ถ้าไม่อยากให้ผู้เล่นเห็นปุ่ม ให้ปิดที่สวิตช์ "แสดงปุ่ม" ในแท็บ ไม่ใช่เอาออกจากเลย์เอาต์ (เอาออกทั้งสองที่ ระบบจะเติมกลับ) · ปุ่มอื่นที่เพิ่มทีหลังให้ใส่ id ใน `ADDED_LATER` ด้วย

## แท็บ /admin "มีอะไรใหม่" (หมวดสื่อสาร)

- ชื่อแท็บ "ประกาศ" เดิม (ประกาศถึงทุกคนทางแชท/แบนเนอร์ สวิตช์ `broadcast`) เป็นคนละอย่างกัน จึงตั้งชื่อแท็บนี้ว่า "มีอะไรใหม่"
- สิทธิ์: `news` (ดูรายการ — owner + GM) และ `newsEdit` (เพิ่ม/แก้/ซ่อน/ลบ + สวิตช์ — owner เท่านั้น) · ปรับต่อ role ได้ในแท็บสิทธิ์
- ทำได้: เพิ่มประกาศ (หัวข้อ + บรรทัดละหนึ่งเรื่อง) · แก้ · ซ่อน/แสดงอีกครั้ง (ซ่อน = หายจากผู้เล่น ย้อนกลับได้) · ลบถาวร (ถามยืนยัน) · แต่ละการ์ดบอกว่าใครลง และผู้เล่นเห็นอยู่หรือเก่าเกิน 5 อันแล้ว
- **สวิตช์ 2 อัน** (เก็บใน `settings` key `news_switches` เฉพาะค่าที่ต่างจากในโค้ด):
  - แสดงปุ่มในเกม — ค่าในโค้ด **เปิด** (ปุ่มไม่มีประกาศก็ไม่เสียหาย: เปิดแล้วขึ้น "ยังไม่มีประกาศอัปเดต")
  - เด้งหน้าต่างเองครั้งแรกหลังอัปเดต — ค่าในโค้ด **ปิด**
- ทุกการเปลี่ยนมีผลกับผู้เล่นออนไลน์ทันที และลง `admin_audit`: `news-add`, `news-edit`, `news-hide`, `news-delete`, `news-switches`
- ข้อจำกัด (server ตรวจทุกช่อง ผิด = 400 ไม่ลง audit): หัวข้อ 1–60 ตัวอักษร · 1–12 บรรทัด · บรรทัดละ 1–120 ตัวอักษร · ตัดอักขระควบคุม/ช่องว่างซ้ำออก บรรทัดว่างทิ้ง · แสดงด้วย `textContent` (ไม่ใช่ HTML) · ประกาศที่ลงสูงสุดที่แท็บแสดง 100 อัน

## ลงตอน /ship (อัตโนมัติ)

- ขั้นท้ายของ `/ship` ([.claude/skills/ship/SKILL.md](../../.claude/skills/ship/SKILL.md)) สรุปสิ่งที่ขึ้นรอบนั้นเป็นภาษาผู้เล่นสั้น ๆ (ข้ามงานที่ผู้เล่นไม่เห็น: เทสต์ เครื่องมือ admin ล้วน เอกสาร) แล้วลงประกาศ — เจ้าของเลือก "ขึ้นเลย แก้ทีหลังได้" ไม่ต้องรออนุมัติ แก้/ซ่อน/ลบได้ที่แท็บนี้
- ลงด้วย `npm run add-news` **บน VPS หลัง deploy เสร็จ** โดยส่ง JSON ทาง stdin (ไม่เขียนไฟล์ใน `~/MULTIVERSE` เพราะ `tools/deploy.sh` ไม่ยอม deploy ถ้า git status ไม่ว่าง และไทยผ่าน ssh quoting ได้ยาก):

  ```
  ssh -o BatchMode=yes multiverse-vps "cd MULTIVERSE && npm run -s add-news -- --json -" < news.json
  ```

  `news.json` = `{ "title": "...", "lines": ["...", "..."], "key": "<commit 7 ตัวของ main ที่ขึ้น>" }` · `key` ทำให้รันซ้ำไม่ลงซ้ำ (มี key นี้แล้ว = ข้าม) · ตัวตรวจค่าตัวเดียวกับแท็บ /admin · ลง audit ในชื่อ `command line`
- สคริปต์เขียน DB จริงตรง ๆ (WAL + `busy_timeout` 5 วิ ปลอดภัยขณะ server รัน เหมือน `npm run admin-role`) · server รันโค้ดใหม่ถึงจะมีตาราง `news` (สร้างตอน `new Db`) จึงต้องรันหลัง deploy · server **เช็ก `settings.news_rev` ทุก 5 วิ** (`GameWorld.newsPoll`) ถ้าเปลี่ยนก็ส่ง `news` ให้ทุกคนออนไลน์ → จุดแดงขึ้นเองภายในไม่กี่วินาที ไม่ต้องรีสตาร์ท (ถ้า server ไม่ได้รัน ผู้เล่นได้ตอนเข้าเกมครั้งถัดไป)
- เครื่องบ้าน/dev: `DB_FILE=… npm run add-news -- --json -` ลง DB ของ dev ได้เหมือนกัน
