## เข้าสู่ระบบด้วย Google (เจ้าของตกลง 2026-11-15)

- โค้ด: `server/google.ts` (flow) · `server/google-api.ts` (route + การ์ด /admin) · ตาราง `account_google` (account_id, sub = รหัสบัญชี Google, email, name, linked_at) · Google 1 บัญชี ↔ บัญชีเกม 1 บัญชี
- **flow (authorization code + PKCE ทำที่ server):** `POST /api/auth/google/start { mode, guestToken? }` → server จำ state + PKCE verifier + nonce 10 นาที → หน้า Google → `GET /api/auth/google/callback` → server แลก code กับ Google เอง (client secret + verifier) ตรวจ `iss` `aud` `exp` `nonce` และอีเมลที่ยืนยันแล้ว → ส่งกลับ `/#google=<ticket>` (ticket ใช้ครั้งเดียว 60 วิ ไม่มี token login ใน URL) → หน้าเกม `POST /api/auth/google/finish { ticket, username? }`
- **3 โหมด:** `login` (Google ที่ผูกแล้ว = เข้าบัญชีนั้น · ยังไม่ผูก = ตั้งชื่อผู้ใช้เอง แล้วได้บัญชีใหม่ที่ไม่มีรหัสผ่าน · ถ้าเบราว์เซอร์มี Guest ตัวละคร Guest ย้ายเข้าบัญชีใหม่เหมือนสมัครปกติ) · `link` (ผูก Google กับบัญชีที่ login อยู่ ชื่อผู้ใช้/รหัสผ่านเดิมยังใช้ได้) · `upgrade` (Guest → บัญชี Google ตัวละครครบ · ถ้า Google นั้นผูกบัญชีอื่นแล้ว = ไม่ยอม บอกให้ login บัญชีนั้นแทน)
- **กัน CSRF:** start ตั้ง cookie `mv_gbind` (HttpOnly, SameSite=Lax, Path `/api/auth/google`, 10 นาที, Secure บน https) เก็บ hash ไว้กับ state · callback และ finish ต้องมา cookie เดียวกัน ไม่ตรง = ไม่ยอม (กันคนอื่นส่งลิงก์ Google/ticket ของตัวเองมาให้กดแล้ว login/ผูกผิดบัญชี)
- ตรวจแบนก่อน login · จำกัด start 30 ครั้ง/10 นาที/IP · ชื่อผู้ใช้กติกาเดียวกับสมัคร
- **ผู้เล่น:** ปุ่ม "เข้าสู่ระบบด้วย Google" ที่หน้า Login (ซ่อนเมื่อปิดหรือไม่มีไฟล์) · หน้าเลือกตัวละคร และเมนูระบบในเกม → ตั้งค่า: ผูก / ยกเลิกผูก Google อยู่ในหน้าต่าง "จัดการบัญชี" (ด้านล่าง; ยกเลิกผูกได้เฉพาะบัญชีที่มีรหัสผ่าน ไม่งั้นเข้าไม่ได้อีก · จากในเกม = ออกจากเกมก่อน แล้วไป Google ต่อเอง) · หน้า Guest: "บันทึกตัวละครด้วย Google"
- **"เลือกตัวละคร" ในเมนูเกม** (เจ้าของ 2026-11-26): โหลดหน้าใหม่แล้วขึ้นหน้าเลือกตัวละคร "กำลังโหลด…" ระหว่างเช็กการล็อกอินกับ server ไม่โชว์หน้า Login แวบ · หน้า Login ขึ้นเฉพาะเมื่อการล็อกอินที่จำไว้ใช้ไม่ได้แล้ว (`OnlineMenu.open(goToCharacters)`, `src/client/menu.ts`) · ไม่มีค่าใน /admin (แก้หน้าตาการรอ ไม่มีตัวเลขหรือพฤติกรรมให้ปรับ)
- บัญชี Google อย่างเดียวไม่มีรหัสผ่าน (`pass_hash` ว่าง) จนกว่าเจ้าของบัญชีตั้งเองในหน้า "จัดการบัญชี" (ด้านล่าง) · ถ้า admin ยกเลิกการผูกบัญชีที่ยังไม่มีรหัส ต้องรีเซ็ตรหัสผ่านให้ถึงจะเข้าได้
- **ไฟล์ของ Google (ห้าม commit):** JSON ที่ดาวน์โหลดจาก Google Cloud Console (web client) server หาที่แรกที่เจอ: env `GOOGLE_OAUTH_FILE` → `server/data/google-oauth.json` → `~/secrets/google-oauth.json` → `~/secrets/client_secret_….json` (ถ้ามีไฟล์เดียว ใช้ชื่อเดิมจาก Google ได้เลย) · อ่านใหม่ทุกครั้ง วางไฟล์แล้วไม่ต้องรีสตาร์ท · บน VPS คัดไปที่ `~/secrets/` ด้วย scp
- **redirect URI:** `<origin>/api/auth/google/callback` ต้องอยู่ทั้งใน Google Cloud Console และในไฟล์ JSON (ดาวน์โหลดใหม่หลังเพิ่ม) · server เลือกตัวที่ตรงกับ origin ที่ผู้เล่นเปิด (`https://play.multiverse-game.com` / `http://localhost:5173` ตอน dev) ไม่ตรง = ไม่ให้เริ่ม และ log บอกว่าต้องเพิ่มอะไร
- **/admin:** แท็บ Server การ์ด "เข้าสู่ระบบด้วย Google" (สวิตช์ `googleLogin` owner): เปิด/ปิดปุ่ม (settings `google_login` = '0' ตอนปิด ไม่มีแถว = เปิด) · บอกว่าเจอไฟล์ที่ไหน client id ลงท้ายอะไร · รายชื่อบัญชีที่ผูก (อีเมล ชื่อ ผูกเมื่อ มีรหัสผ่านไหม) + ยกเลิกการผูก · ตาราง "ผู้ใช้ทั้งหมด" มีป้าย `G` และตัวกรอง "ผูก Google" · audit `google-login` / `google-unlink`
- เทสต์: `tests/google-login.test.ts` (Google ปลอมผ่าน `GOOGLE_TOKEN_URL`)

## จัดการบัญชีของผู้เล่น (เจ้าของตกลง 2026-11-27)

ทุกวิธี login (Google, ชื่อผู้ใช้/รหัสผ่าน, Guest) เข้าบัญชีเกมเดียวกัน ไม่มีตัวละครหาย · โค้ด `server/account-api.ts` (API) · `src/client/accountUi.ts` (หน้าต่าง) · เทสต์ `tests/account-manage.test.ts`

- **หน้าต่าง "จัดการบัญชี"**: ปุ่ม "⚙ จัดการบัญชี" ในหน้าเลือกตัวละคร (แถวใต้ชื่อบัญชี บอก 🔑 รหัสผ่าน / Google: อีเมล) และในเกม เมนูระบบ → ตั้งค่า แถว "บัญชี" (หน้าตั้งค่าแบบเก่าก็มีปุ่ม) · บอกว่าเข้าได้ทางไหน (ชื่อผู้ใช้ + รหัสผ่าน ✔/✖, Google ✔/✖ + อีเมล) · `GET /api/account` (`AccountInfoResponse`)
- **ตั้งรหัสผ่าน (บัญชีที่สมัครด้วย Google)**: ไม่ต้องใส่รหัสเดิม · server ยอมเฉพาะบัญชีที่ยังไม่มีรหัส (UPDATE แบบมีเงื่อนไข กดพร้อมกัน 2 ที่ได้อันเดียว) · ตั้งแล้วเข้าได้ทั้ง Google และชื่อผู้ใช้/รหัส และยกเลิกผูก Google ได้ (ยังไม่มีรหัส = ปุ่มยกเลิกผูกกดไม่ได้ server ก็ไม่ยอม)
- **เปลี่ยนรหัสผ่าน**: ต้องใส่รหัสเดิม · `POST /api/account/password { password, oldPassword? }` · ตั้ง/เปลี่ยน/กู้แล้ว **token อื่นทั้งหมดของบัญชีถูกลบ** (เครื่องอื่นต้องเข้าใหม่) token ของเครื่องที่กดยังใช้ได้
- **ลืมรหัสผ่าน (ไม่มีระบบอีเมล)**: บัญชีที่ผูก Google → "เข้าสู่ระบบด้วย Google" แล้วเปิด "จัดการบัญชี" ตั้งรหัสใหม่ได้โดยไม่ต้องใส่รหัสเดิม ภายใน **10 นาที** หลัง login ด้วย Google (เจ้าของเลือก) · server ดูจาก `sessions.google_at` (เวลาที่ token นั้นได้มาจาก Google login, NULL = login ด้วยรหัส) + บัญชียังผูก Google อยู่ · ใช้ได้ครั้งเดียวต่อ login (ตั้งแล้วล้าง `google_at`) · token จาก login ด้วยรหัสผ่านกู้ไม่ได้ · หน้า Login มีลิงก์ "ลืมรหัสผ่าน?" บอกวิธีนี้ (ไม่ได้ผูก Google = แจ้งผู้ดูแลให้รีเซ็ตรหัสในหน้าบัญชี /admin เหมือนเดิม)
- **เปลี่ยนชื่อผู้ใช้**: ได้**ทุกบัญชี**ที่ไม่ใช่ Guest (เจ้าของเลือก) **1 ครั้ง / 30 วัน** (เจ้าของเลือก, `accounts.username_changed_at`, NULL = ยังไม่เคยเปลี่ยน) · `checkUsername` + ตรวจซ้ำใน transaction (ไม่สนตัวพิมพ์ ชื่อตัวเองต่างตัวพิมพ์ไม่นับว่าซ้ำ) · `POST /api/account/username { username }` · ชื่อเก่าว่างให้คนอื่นใช้ได้ทันที · ระบบที่ผูกกับบัญชีใช้ id ไม่ใช่ชื่อ (เพื่อน คลัง ตลาด จดหมาย ห้ามรายงาน) จึงไม่ต้องย้ายอะไร · ชื่อใน log/audit/แชท/play_sessions/topups เป็นชื่อ ณ ตอนนั้น (ไม่แก้ย้อนหลัง) · คนที่ออนไลน์อยู่ server เปลี่ยนชื่อในหน่วยความจำให้ด้วย (`world.renameAccount`)
- **Guest บันทึกตัวละครในเกม (ไม่ต้องออก)**: ปุ่ม "บันทึกตัวละคร" ที่ป้าย Guest บน HUD และในเมนูระบบ → ตั้งค่า แถว "บัญชี" → หน้าต่างให้เลือก ตั้งชื่อผู้ใช้/รหัสผ่าน หรือ "ใช้บัญชี Google" (ออกจากเกมไปหน้า Google แบบเดิม) · `POST /api/account/guest-upgrade { username, password }` (ส่งด้วย token ของ Guest) ใช้ `upgradeGuest` เดิม = id บัญชีเดิม ตัวละคร/เควส/อัลบั้มครบ token Guest เดิมตาย ได้ token ใหม่ · หลังบันทึก หน้าโหลดใหม่แล้วเข้าตัวละครเดิมให้เอง (`RESUME_CHAR_KEY` ใน sessionStorage) อยู่แมพ/CH/จุดเดิม (การโหลดหน้า = drop server จำจุดไว้ 60 วิ) ไม่ต้องกดเข้าเกมเอง · เจ้าของตกลงแบบโหลดหน้าใหม่ (2026-11-27, เห็นหน้าโหลดสั้น ๆ ไม่เกิน ~10 วิ) แทนการต่อ WebSocket ในหน้าเดิม เพราะหน้าต่างในเกมหลายอันจำสถานะ Guest ตั้งแต่เปิดเกม
- **หน้ายืนยันก่อนเชื่อมบัญชี Google**: ผล `needName` ของ `/api/auth/google/finish` บอก `mode` และ `guestChar` (ชื่อ + Lv อ่านที่ server จาก Guest ของ flow ไม่เชื่อ client)
  - กด "เข้าสู่ระบบด้วย Google" จากเบราว์เซอร์ที่มี Guest และ Google นั้นยังไม่ผูกบัญชีไหน → ต้องเลือกก่อน: **ก "ใช้ Guest ที่อยู่: “ชื่อ” Lv.N"** (ตัวละครย้ายเข้าบัญชีใหม่) หรือ **ข "สร้างบัญชีเปล่า"** (Guest ยังอยู่ในเบราว์เซอร์ตามเดิม ไม่แตะ token/ตัวละคร) · ส่ง `useGuest: true` เฉพาะตอนเลือก ก ไม่ส่ง = บัญชีเปล่า
  - โหมด `upgrade` (ปุ่ม "บันทึกตัวละครด้วย Google"/"ใช้บัญชี Google") ขึ้นยืนยันแบบเดียวกัน บอกตัวละครและอีเมล ปุ่ม "ยืนยัน ย้ายตัวละคร" / "ยกเลิก" · upgrade ย้าย Guest เสมอ Guest หายระหว่างทาง = ไม่สร้างบัญชี
- **จำกัดความถี่** (`AttemptLimiter`): รหัสผ่าน 10 ครั้ง/10 นาที/บัญชี + 30/IP (นับทุกครั้ง รวมรหัสเดิมผิด) · ชื่อที่ซ้ำ (เปลี่ยนชื่อ/Guest บันทึก) 20 ครั้ง/10 นาที/IP
- **ลง audit** (ผู้ทำ = "ผู้เล่น"): `account-password-set` / `-change` / `-recover`, `account-rename` (ชื่อเก่า → ใหม่), `guest-upgrade`, `google-register` (สมัครด้วย Google บัญชีเปล่า), `google-unlink` (ผู้เล่นยกเลิกเอง) · **รหัสผ่านไม่ลง log หรือ audit**
- **/admin:** แท็บ Server การ์ด "บัญชีผู้เล่น" (สวิตช์ `accountAuth` owner): สวิตช์ ตั้งรหัสให้บัญชี Google (`setPassword`) · Guest บันทึกในเกม (`guestUpgrade`) · เปลี่ยนรหัส (`changePassword`) · เปลี่ยนชื่อผู้ใช้ (`rename`) · กู้รหัสด้วย Google (`recover`) + เปลี่ยนชื่อได้ทุกกี่วัน (0 = ไม่จำกัด, ≤365) + นาทีที่กู้รหัสได้ (1–60) · ทุกอย่างเปิด 30 วัน 10 นาทีในโค้ด (`ACCOUNT_TUNING_DEFAULT` ใน `src/shared/api.ts`) · settings key `account_tuning` เก็บเฉพาะที่ต่าง · server ตรวจสวิตช์ทุก request · ลง audit `account-auth` · ตาราง "ผู้ใช้ทั้งหมด" มีป้าย 🔑 (มีรหัสผ่าน) และ `G` (ผูก Google)
- หน้า `/privacy` บอกข้อมูลใหม่ (เวลาเปลี่ยนชื่อ, login แต่ละครั้งเข้าด้วย Google ไหม) ปรับปรุง 27 พ.ย. 2569

## Guest

- Guest = บัญชีชั่วคราวบน server (`accounts.is_guest = 1`) มีตัวละคร 1 ตัว เบราว์เซอร์เก็บแค่ token (`multiverse-guest-token`) ห้ามเชื่อข้อมูลตัวละครจากเบราว์เซอร์
  - ถูกลบ (ตัวละครด้วย) เมื่อไม่ได้ออนไลน์เกิน 24 ชม. นับจาก `last_online` · server ไล่ลบตอนเปิดและทุก 1 ชม. คนที่ออนไลน์อยู่ไม่ถูกลบ
  - สมัครสมาชิกจากเบราว์เซอร์ที่มี Guest → บัญชี Guest กลายเป็นบัญชีจริง ตัวละครย้ายมาด้วย (นับใน 3 ช่อง) · เข้าสู่ระบบบัญชีเดิมไม่ย้าย
  - "เริ่ม Guest ใหม่" ลบ Guest เดิมเมื่อสร้างตัวใหม่สำเร็จ · สร้าง Guest ได้ไม่เกิน 5 ตัวต่อ IP ต่อชั่วโมง (`GUEST_PER_IP_HOUR` ใน `src/shared/api.ts`)
  - ระหว่างเล่นมีป้าย Guest บน HUD · ไม่มีบทนำ The Seeker ตอนเริ่ม (คุยเองได้)

## หน้าผู้ดูแล /admin

- หน้าผู้ดูแล `/admin` (`admin.html`, `src/admin/`, API ใน `server/admin.ts`) ใช้บัญชีเกมเดิม · role ใน `accounts.admin_role`: `owner` (ทุกอย่างเสมอ), `gm` (มากับระบบ) และ role ที่ owner สร้างเอง เช่น `tester` · แต่ละ role ใช้เครื่องมือได้ตามที่ติ๊กไว้ในแท็บ "สิทธิ์" (ด้านล่าง)
  - **หน้าตาใหม่ (เจ้าของตกลง 2026-11-18)**: เมนูด้านซ้ายแสดงทุกหมวดและทุกแท็บพร้อมกัน (กดครั้งเดียว · มือถือ/จอแคบ ≤ 860px เป็นลิ้นชักจากปุ่ม ☰) · ช่องค้นหาบนแถบบน (กด `/` ได้): หาชื่อแท็บ การ์ดของทุกแท็บ (`SEARCH_INDEX` ใน `src/admin/main.ts` ชื่อการ์ด + คำค้น เพิ่มการ์ดใหม่ให้เพิ่มที่นี่ด้วย) และหัวข้อ/ข้อความในแท็บที่เปิดอยู่ กดผลแล้วพาไปที่การ์ดนั้น · แท็บที่เปิดอยู่เก็บในลิงก์ (`/admin#balance`) รีโหลดแล้วกลับที่เดิม · คำอธิบายในการ์ดที่ยาว ≥ 140 ตัวอักษร (ข้อความล้วน) โชว์บรรทัดเดียว + "อ่านต่อ" · แท็บปรับสมดุล: ปุ่มสารบัญการ์ดติดด้านบน การ์ดพับได้ (กดหัวการ์ด) จุดเหลืองที่การ์ดที่แก้แล้วยังไม่บันทึก แถบบันทึกติดล่างจอ · ธีมเหล็กดำทองเดิม หมวดเดิม · โค้ดหน้าตาอยู่ใน `src/admin/ui.ts` + `admin.css` เปลี่ยนแค่หน้าตา สิทธิ์และ API เดิม
  - **โครงหน้า (เจ้าของตกลง 2026-11-11, แถบแท็บสองแถวถูกแทนด้วยเมนูซ้ายแล้ว)**: 6 หมวด · ผู้เล่น (ออนไลน์ / ผู้ใช้และตัวละคร) · ประวัติ (สถิติ / การเข้าเล่น / แชท / เทรด / ประวัติ (audit)) · สื่อสาร (จดหมาย / รายงาน / ประกาศ) · ปรับเกม (ปรับสมดุล / ระบบสกิล / การ์ด / ล็อกอินรายวัน / แคชช็อป — ระบบสกิลแยกจากปรับสมดุล 2026-11-19 ใช้สวิตช์ `balance` เดิม) · หน้าตา (ลูกแก้วตีบวก / ของแต่งตัว / จัดการของแต่งตัว) · ระบบ (Server / สิทธิ์) · แท็บที่ role ไม่มีสิทธิ์ซ่อน หมวดที่ไม่เหลือแท็บซ่อนด้วย · "ประกาศ" แยกออกจากแท็บ Server (ยังเป็นสวิตช์ `broadcast` เดิม) · หมวดอยู่ใน `CATEGORIES` ของ `src/admin/main.ts` และชื่อหมวดเดียวกับ `FEATURE_GROUPS` ที่แท็บ "สิทธิ์" ใช้จัดกลุ่มเครื่องมือ · แท็บ "ผู้ใช้และตัวละคร" รวม "ค้นหาตัวละคร" (สวิตช์ `charView`) กับตารางบัญชี (สวิตช์ `users`) ไว้แท็บเดียว: role ที่มีแค่ `charView` เห็นแค่ช่องค้นหาตัวละคร ที่มีแค่ `users` เห็นแค่ตารางบัญชี · ตัวกรอง "ออนไลน์" ในตารางบัญชีถูกเอาออก (ซ้ำแท็บออนไลน์) · ส่งข้อความหาผู้เล่นคนเดียวทำได้จากปุ่ม 📢 ท้ายแถวในแท็บออนไลน์เท่านั้น แท็บ "ประกาศ" ส่งถึงทุกคน · สิทธิ์ที่ server ตรวจไม่เปลี่ยน
  - แท็บ admin ที่เปิดค้างข้ามการอัปเดต server จะขึ้นแถบ "หน้า admin มีเวอร์ชันใหม่" + ปุ่มโหลดหน้าใหม่ (เทียบชื่อไฟล์ `assets/admin-<hash>.js` ของหน้าที่เปิดอยู่กับที่ server เสิร์ฟตอนนี้ ตรวจตอนเปลี่ยนแท็บ, กลับมาที่หน้าต่าง และทุก 2 นาที · ไม่โหลดใหม่เอง กันฟอร์มที่พิมพ์ค้างหาย · ไม่ทำงานใน `npm run dev`)
  - ตั้ง owner ได้จาก command line เท่านั้น: `npm run admin-role -- <ชื่อผู้ใช้> owner|gm|none|<รหัส role ที่สร้างในหน้า /admin>` (DB ตาม `DB_FILE` ค่าเริ่มต้นคือ DB จริง)
  - server ตรวจ role ทุก request · แก้ตัวละครออนไลน์ผ่าน Player ตัวจริงใน `server/world.ts` แล้วเซฟทันที · ทุกการกระทำลงตาราง `admin_audit`
  - เพดานต่อครั้ง (ทอง 1,000,000 / ไอเทม 10 ชิ้น) อยู่ใน `src/shared/admin.ts`
  - แท็บ "จดหมาย" (ส่งจดหมาย/ของแนบถึงผู้เล่น ดูประวัติ ดึงกลับ) คือสวิตช์ `mail` ใน `FEATURE_ROLES` (owner เท่านั้นตอนนี้) · กติกาอยู่ใน [mail.md](mail.md)
  - เสกไอเทมได้ทุกชนิดจากฟอร์มเดียว: ช่อง "ชนิด" มีอุปกรณ์ + กลุ่ม "ยา" (HP/MP × เล็ก/กลาง/ใหญ่) + "หินช่างตีเหล็ก" (หินกันระดับลด/หินตีบวก) · เลือกยา/หินแล้วซ่อนความหายาก/ตีบวก/เลเวล/สเตตัส · owner และ GM เสกยา/หินได้ · นับทีละขวด/ก้อน ครั้งละ 1–10 · เข้ากระเป๋าแบบเก็บของ (เติมกองเดิมก่อน แล้วใช้ช่องว่าง) ใส่ไม่หมด = ใส่เท่าที่ได้แล้วบอก "ใส่ได้ n/m" · API `items` ส่ง `{ kind: 'potion', potion, size, count }` / `{ kind: 'stone', stone, count }` (`adminStack`, `addStackToBag` ใน `src/shared/admin.ts`)

    - **เสกของเป็นเซต** (เจ้าของ 2026-11-21): สวิตช์ `spawnSet` (owner+GM, ต้องมี `charEdit` ด้วย) · API `POST /api/admin/characters/:id/itemset` `{ classId?, rarity, tier 1–5, level 1–80, plus 0–15 }` · ทุกช่องสวมใส่ (ทุกชนิด + แหวน 2 วง ≤ 10 ชิ้น) ชนิดที่ดีที่สุดที่เลเวลนั้นใส่ได้ (ช่องที่ยังไม่มีชนิดที่เลเวลนั้นถูกข้าม) · ทุกแถวสเตตัสอยู่กลางช่วง tier ที่เลือก · อาชีพเริ่มต้น = ตัวเป้าหมาย เลือกอาชีพอื่นได้ · เข้ากระเป๋า กระเป๋าว่างไม่พอ = ไม่เสกเลย · server ตรวจทุกค่า (`buildGearSet` ใน `src/shared/admin.ts`) · ลง audit `items` · เทสต์ `tests/admin-spawn-set.test.ts` · ฟอร์มเสกเดี่ยว: เปลี่ยนจากยา/หินเป็นอุปกรณ์ จำนวนกลับเป็น 1
    - แก้ไอเทม = สวิตช์ `itemEdit` (owner และ GM ตามที่เจ้าของเลือก ต้องมี `users` เพื่อเปิดหน้าบัญชี) · แก้ได้ทุกอย่าง: ชนิด ความหายาก เลเวล (≥ ขั้นต่ำของชนิด) อาชีพ ชื่อ (จากรายชื่อของชนิด/ความหายากนั้น) ตีบวก 0–15 pity 0–100 (`ADMIN_PITY_MAX`) และสเตตัสทุกบรรทัด (เพิ่ม/ลบ/ชนิด/ค่า ≤ 10 แถว ค่าได้ถึง ×2 ของค่าสูงสุดปกติเหมือนฟอร์มเสก tier/min–max คำนวณจากค่าเอง) · ยา/หินแก้จำนวน 1–10 · ลบไอเทมได้ (ถามยืนยัน) · uid เดิมคงไว้

  - แท็บ **"สิทธิ์"** (owner เท่านั้น, ตกลงกับเจ้าของ 2026-11-10, API ใน `server/admin-roles.ts`):
    - ทุก role มีรายการเครื่องมือให้ติ๊ก (ชื่อไทย + คำอธิบาย แบ่งกลุ่ม · `FEATURE_INFO` ใน `src/shared/admin.ts`) ตั้งแต่ไม่กี่อย่างจนถึงทั้งหมด · มีผลทันทีที่ request ถัดไป ไม่ต้องออกจากระบบ
    - เครื่องมือพื้นฐานก็เป็นสวิตช์: `online` (ดูออนไลน์), `charView` (ค้นหา/ดูตัวละคร), `charEdit` (เลเวล/ทอง/เสกของ), `kick`, `teleport` · GM ได้ครบเหมือนเดิม
    - `staffTarget` = แตะบัญชี/ตัวละครของทีมงานคนอื่นได้ (แบน รีเซ็ตรหัส แก้ตัวละคร) · ไม่มี = แตะได้แค่ผู้เล่นธรรมดาและบัญชีตัวเอง · บัญชี owner ไม่มีใครแตะได้เสมอ · GM ไม่มีเป็นค่าเริ่มต้น
    - ค่าเริ่มต้นอยู่ที่ `FEATURE_ROLES` · ตาราง `admin_roles` เก็บเฉพาะที่ owner เปลี่ยนจากค่าเริ่มต้น (`features` = JSON feature → true/false) DB เดิมจึงทำงานเหมือนเดิม และเครื่องมือที่เพิ่มทีหลังได้ค่าตาม `FEATURE_ROLES` · role ใหม่เริ่มแบบไม่มีอะไรเลย
    - สร้าง role: รหัสภาษาอังกฤษ a–z 0–9 _ (2–20 ตัว, เปลี่ยนไม่ได้, ห้าม owner/gm/none/null/admin) + ชื่อที่แสดง (≤ 20 ตัว ห้ามซ้ำ, แก้ได้ = "เปลี่ยนชื่อ") · สูงสุด 20 role
    - `owner` แก้/ลบไม่ได้ · `gm` แก้เครื่องมือและชื่อได้ ลบไม่ได้ · **ลบ role ที่ยังมีบัญชีใช้อยู่ไม่ได้** ต้องเปลี่ยน role ของบัญชีเหล่านั้นก่อน
    - ให้/เปลี่ยน/ถอน role ของบัญชีได้จากแท็บนี้ (ให้ owner ไม่ได้ ตั้งได้จาก command line เท่านั้น · เปลี่ยน role ของ owner ไม่ได้)
    - ป้าย role ในหน้า /admin และชื่อผู้ประกาศใช้ชื่อที่แสดงของ role · ในเกมไม่มีป้าย role (ข้อความแจ้งผู้เล่นตอนถูกแก้ตัวละครยังขึ้นว่า "GM")
    - ทุกการเปลี่ยนลง `admin_audit`: `role-create`, `role-edit` (ชื่อเดิม → ใหม่, เพิ่ม/เอาออก), `role-delete`, `grant`/`revoke` (role เดิม → ใหม่)
  - **ของ owner เท่านั้นตลอด (ไม่มีสวิตช์)**: แท็บสิทธิ์, ประวัติ (audit), รีสตาร์ท/ปิด server, ลบบัญชี/ตัวละคร, ตั้ง owner
  - แบน: คอลัมน์ `accounts.ban_until` / `ban_reason` · login และการเข้าโลกถูกปฏิเสธพร้อมเหตุผล
  - ประวัติ: `play_sessions` (เข้า-ออก, IP, GPU, ping/FPS เฉลี่ย) เก็บ 90 วัน, `chat_log` เก็บ 30 วัน, `online_samples` (จำนวนคนออนไลน์ทุก 1 นาที) เก็บ 90 วัน · ตัวเลขอยู่ที่ `HISTORY_DAYS` ใน `src/shared/admin.ts` · ลบของเก่าทุกชั่วโมง
  - ตารางการเข้าเล่น (แท็บ "การเข้าเล่น" และแท็บ "การเข้าเล่น" ในหน้าบัญชี ซึ่งกรองเฉพาะบัญชีนั้น ใช้ `sessionsTable()` ตัวเดียวกันใน `src/admin/main.ts`): เรียง/แบ่งหน้าที่ server ทุกแถวที่เก็บไว้ · กดหัวคอลัมน์ (หรือช่อง "เรียงตาม" + ปุ่ม ▲/▼) · ค้นหาชื่อผู้ใช้/ตัวละคร/IP (บางส่วน ไม่สนตัวพิมพ์ ≤ 50 ตัว, Guest ค้นด้วยคำว่า "Guest") · ช่วงวันที่เข้าเล่น (ตามเวลาเครื่องผู้ดู ทั้งวัน) · 25/50/100 แถวต่อหน้า + เลขหน้า
    - "นานเท่าไร" ของคนที่กำลังเล่นนับถึงตอนนี้ · ค่าว่าง (ไม่ทราบ, ไม่มี GPU/Ping/FPS รวมถึง Ping/FPS ของคนที่ยังเล่นอยู่ซึ่งยังไม่ลง DB) อยู่ท้ายตารางเสมอทั้งเรียงขึ้นและลง
    - API `GET /api/admin/sessions?sort=&dir=&page=&size=&q=&from=&to=&account=` คืน `{ rows, total, page, size }` (`SessionPage`) · server ตรวจทุกค่า ผิด = 400 · คอลัมน์เรียงมาจาก whitelist `SESSION_SORTS` (`sessionSortSql` ใน `server/db.ts`) ไม่เอาค่าจาก client ใส่ SQL · หน้าเกินจำนวน = หน้าสุดท้าย
    - ตารางกลายเป็นการ์ดเมื่อกล่องแคบกว่า 700px (มือถือ และในหน้าบัญชี) ด้วย container query
