# หน้า Login, Guest และหน้าผู้ดูแล /admin

สรุปสั้นอยู่ใน [CLAUDE.md](../../CLAUDE.md) · สำรอง/กู้คืน DB: [server-ops.md](server-ops.md)

## หน้า Login

- หน้าแรกคือแผง **Login**: ฟอร์มเข้าสู่ระบบ/สมัคร แล้วตามด้วยปุ่ม **Guest Login** (ไม่มี Singleplayer แล้ว เซฟ SP เก่าในเบราว์เซอร์ถูกทิ้ง ไม่ import)
  - ปุ่ม Guest Login เปิดใช้งาน (เจ้าของสั่งเปิดกลับ 2026-11-12 หลังเคยปิดเป็นแค่รูป) ปิดอีกครั้งได้ด้วย `GUEST_LOGIN_ENABLED` ใน `src/client/menu.ts`

## Guest

- Guest = บัญชีชั่วคราวบน server (`accounts.is_guest = 1`) มีตัวละคร 1 ตัว เบราว์เซอร์เก็บแค่ token (`multiverse-guest-token`) ห้ามเชื่อข้อมูลตัวละครจากเบราว์เซอร์
  - ถูกลบ (ตัวละครด้วย) เมื่อไม่ได้ออนไลน์เกิน 24 ชม. นับจาก `last_online` · server ไล่ลบตอนเปิดและทุก 1 ชม. คนที่ออนไลน์อยู่ไม่ถูกลบ
  - สมัครสมาชิกจากเบราว์เซอร์ที่มี Guest → บัญชี Guest กลายเป็นบัญชีจริง ตัวละครย้ายมาด้วย (นับใน 3 ช่อง) · เข้าสู่ระบบบัญชีเดิมไม่ย้าย
  - "เริ่ม Guest ใหม่" ลบ Guest เดิมเมื่อสร้างตัวใหม่สำเร็จ · สร้าง Guest ได้ไม่เกิน 5 ตัวต่อ IP ต่อชั่วโมง (`GUEST_PER_IP_HOUR` ใน `src/shared/api.ts`)
  - ระหว่างเล่นมีป้าย Guest บน HUD · ไม่มีบทนำ The Seeker ตอนเริ่ม (คุยเองได้)

## หน้าผู้ดูแล /admin

- หน้าผู้ดูแล `/admin` (`admin.html`, `src/admin/`, API ใน `server/admin.ts`) ใช้บัญชีเกมเดิม · role ใน `accounts.admin_role`: `owner` (ทุกอย่างเสมอ), `gm` (มากับระบบ) และ role ที่ owner สร้างเอง เช่น `tester` · แต่ละ role ใช้เครื่องมือได้ตามที่ติ๊กไว้ในแท็บ "สิทธิ์" (ด้านล่าง)
  - **โครงหน้า (เจ้าของตกลง 2026-11-11)**: แถวบนเป็น 6 หมวด กดแล้วเห็นแท็บย่อยในแถวที่สอง (เลื่อนข้างได้บนมือถือ ไม่ล้นหน้า) · ผู้เล่น (ออนไลน์ / ผู้ใช้และตัวละคร) · ประวัติ (สถิติ / การเข้าเล่น / แชท / เทรด / ประวัติ (audit)) · สื่อสาร (จดหมาย / รายงาน / ประกาศ) · ปรับเกม (ปรับสมดุล / การ์ด) · หน้าตา (ลูกแก้วตีบวก / ของแต่งตัว / จัดการของแต่งตัว) · ระบบ (Server / สิทธิ์) · แท็บที่ role ไม่มีสิทธิ์ซ่อน หมวดที่ไม่เหลือแท็บซ่อนด้วย · "ประกาศ" แยกออกจากแท็บ Server (ยังเป็นสวิตช์ `broadcast` เดิม) · หมวดอยู่ใน `CATEGORIES` ของ `src/admin/main.ts` และชื่อหมวดเดียวกับ `FEATURE_GROUPS` ที่แท็บ "สิทธิ์" ใช้จัดกลุ่มเครื่องมือ · แท็บ "ผู้ใช้และตัวละคร" รวม "ค้นหาตัวละคร" (สวิตช์ `charView`) กับตารางบัญชี (สวิตช์ `users`) ไว้แท็บเดียว: role ที่มีแค่ `charView` เห็นแค่ช่องค้นหาตัวละคร ที่มีแค่ `users` เห็นแค่ตารางบัญชี · ตัวกรอง "ออนไลน์" ในตารางบัญชีถูกเอาออก (ซ้ำแท็บออนไลน์) · ส่งข้อความหาผู้เล่นคนเดียวทำได้จากปุ่ม 📢 ท้ายแถวในแท็บออนไลน์เท่านั้น แท็บ "ประกาศ" ส่งถึงทุกคน · สิทธิ์ที่ server ตรวจไม่เปลี่ยน
  - แท็บ admin ที่เปิดค้างข้ามการอัปเดต server จะขึ้นแถบ "หน้า admin มีเวอร์ชันใหม่" + ปุ่มโหลดหน้าใหม่ (เทียบชื่อไฟล์ `assets/admin-<hash>.js` ของหน้าที่เปิดอยู่กับที่ server เสิร์ฟตอนนี้ ตรวจตอนเปลี่ยนแท็บ, กลับมาที่หน้าต่าง และทุก 2 นาที · ไม่โหลดใหม่เอง กันฟอร์มที่พิมพ์ค้างหาย · ไม่ทำงานใน `npm run dev`)
  - ตั้ง owner ได้จาก command line เท่านั้น: `npm run admin-role -- <ชื่อผู้ใช้> owner|gm|none|<รหัส role ที่สร้างในหน้า /admin>` (DB ตาม `DB_FILE` ค่าเริ่มต้นคือ DB จริง)
  - server ตรวจ role ทุก request · แก้ตัวละครออนไลน์ผ่าน Player ตัวจริงใน `server/world.ts` แล้วเซฟทันที · ทุกการกระทำลงตาราง `admin_audit`
  - เพดานต่อครั้ง (ทอง 1,000,000 / ไอเทม 10 ชิ้น) อยู่ใน `src/shared/admin.ts`
  - แท็บ "จดหมาย" (ส่งจดหมาย/ของแนบถึงผู้เล่น ดูประวัติ ดึงกลับ) คือสวิตช์ `mail` ใน `FEATURE_ROLES` (owner เท่านั้นตอนนี้) · กติกาอยู่ใน [mail.md](mail.md)
  - เสกไอเทมได้ทุกชนิดจากฟอร์มเดียว: ช่อง "ชนิด" มีอุปกรณ์ + กลุ่ม "ยา" (HP/MP × เล็ก/กลาง/ใหญ่) + "หินช่างตีเหล็ก" (หินกันระดับลด/หินตีบวก) · เลือกยา/หินแล้วซ่อนความหายาก/ตีบวก/เลเวล/สเตตัส · owner และ GM เสกยา/หินได้ · นับทีละขวด/ก้อน ครั้งละ 1–10 · เข้ากระเป๋าแบบเก็บของ (เติมกองเดิมก่อน แล้วใช้ช่องว่าง) ใส่ไม่หมด = ใส่เท่าที่ได้แล้วบอก "ใส่ได้ n/m" · API `items` ส่ง `{ kind: 'potion', potion, size, count }` / `{ kind: 'stone', stone, count }` (`adminStack`, `addStackToBag` ใน `src/shared/admin.ts`)
  - **ไอเทมในหน้าบัญชี (เจ้าของตกลง 2026-11-11)**: สวมใส่ / กระเป๋า / คลัง แสดงเป็นตารางช่องแบบกระเป๋าในเกม (ไอคอน กรอบสีตามความหายาก +N เลเวล จำนวนกอง · `src/admin/items.ts` ไอคอนสร้างจาก `itemArt` ไม่ import `src/client/icons.ts` เพราะจะลากโค้ด 3D มาด้วย) · กดช่อง = แผงรายละเอียดแบบ tooltip ในเกม (บรรทัดสเตตัส + tier + ช่วง min–max, โบนัสตีบวก, อาชีพที่ใส่ได้, pity, ราคาขาย, uid) ไม่มีส่วนเทียบกับของที่สวมอยู่
    - แก้ไอเทม = สวิตช์ `itemEdit` (owner และ GM ตามที่เจ้าของเลือก ต้องมี `users` เพื่อเปิดหน้าบัญชี) · แก้ได้ทุกอย่าง: ชนิด ความหายาก เลเวล (≥ ขั้นต่ำของชนิด) อาชีพ ชื่อ (จากรายชื่อของชนิด/ความหายากนั้น) ตีบวก 0–15 pity 0–100 (`ADMIN_PITY_MAX`) และสเตตัสทุกบรรทัด (เพิ่ม/ลบ/ชนิด/ค่า ≤ 10 แถว ค่าได้ถึง ×2 ของค่าสูงสุดปกติเหมือนฟอร์มเสก tier/min–max คำนวณจากค่าเอง) · ยา/หินแก้จำนวน 1–10 · ลบไอเทมได้ (ถามยืนยัน) · uid เดิมคงไว้
    - **หมายเหตุ**: GM ที่มี `itemEdit` จึงตั้งสเตตัสเองได้ผ่านการแก้ แม้ไม่มีสวิตช์ `customItem` (เจ้าของเลือก owner+GM)
    - ของที่สวมอยู่: เปลี่ยนเป็นชนิดที่ใส่ช่องอื่นไม่ได้ และต้องเป็นของสายตัวละครและไม่เกินเลเวลตัวละคร
    - ตัวละคร/คลังที่ออนไลน์อยู่แก้ได้ มีผลทันที เซฟทันที **ไม่แจ้งผู้เล่น** (เจ้าของเลือก) · คลังของบัญชีที่ออนไลน์แก้ที่คลังตัวที่ server ถืออยู่ ไม่ใช่ DB · ของที่อยู่ในหน้าต่างเทรดแก้ได้ แต่เทรดจะไม่สำเร็จเพราะของไม่ตรงกับที่เสนอ (กติกาเดิมของเทรด)
    - API `POST /api/admin/items` (`server/admin-items.ts`) `{ place: 'equip'|'bag'|'stash', charId|accountId, key: ช่อง, sig, op: 'save'|'delete', ... }` · `sig` = สิ่งที่หน้าเห็นในช่องนั้น (`entrySig`: uid ของอุปกรณ์ หรือชนิดของกอง) ไม่ตรง = 409 "ของในช่องนี้เปลี่ยนไปแล้ว" · server ตรวจทุกค่า (`editGear` ใน `src/shared/admin.ts` ใช้ `customItem`) · แตะบัญชีทีมงานคนอื่นตามกติกา `staffTarget` เดิม · ลง audit `item-edit` (ช่อง · ของก่อน → หลัง) / `item-delete` · เทสต์ `tests/admin-items-server.test.ts`
  - แท็บ "เทรด" (ประวัติเทรดที่สำเร็จระหว่างผู้เล่น อ่านอย่างเดียว) คือสวิตช์ `tradeLog` ใน `FEATURE_ROLES` (owner เท่านั้นตอนนี้) · กติกาอยู่ใน [trade.md](trade.md)
  - แท็บ "รายงาน" (รายงานปัญหา/ข้อเสนอแนะจากผู้เล่น เปลี่ยนสถานะ ห้ามรายงานต่อบัญชี) คือสวิตช์ `reports` (owner และ GM) และ `reportBan` (owner เท่านั้น) ใน `FEATURE_ROLES` · กติกาอยู่ใน [reports.md](reports.md)
  - แท็บ "ลูกแก้วตีบวก" (ที่ทดลองหน้าตาลูกแก้วตีบวก: ชุดสี รูปทรง ขนาด จำนวนลูก เดินดูได้ · ทดลองไม่เปลี่ยนอะไรในเกม) คือสวิตช์ `orbPreview` ใน `FEATURE_ROLES` (owner และ GM, เจ้าของตั้ง 2026-11-10) · โค้ดอยู่ `src/client/orbPreview.ts` โหลดเมื่อเปิดแท็บเท่านั้น · ตอน `npm run dev` เปิดได้ที่ `/orbs.html` ด้วย (ไม่ถูก build ไปกับเกม) · บันทึกเป็นหน้าตาของทั้งเซิร์ฟได้เฉพาะสวิตช์ `orbLook` (owner เท่านั้น) กติกาอยู่ใน [items-and-forge.md](items-and-forge.md)
  - แท็บ "ของแต่งตัว" (ที่ทดลองตำแหน่งและหน้าตาของปีก สัตว์ขี่ สัตว์เลี้ยง ออร่า แยกรายชิ้น หันได้ 8 ทิศ · ทดลองไม่เปลี่ยนอะไรในเกม) คือสวิตช์ `cosPreview` ใน `FEATURE_ROLES` (owner และ GM, เจ้าของตั้ง 2026-11-10) · บันทึกเป็นค่าของทั้งเซิร์ฟได้เฉพาะสวิตช์ `cosLook` (owner เท่านั้น) กติกาอยู่ใน [cosmetics.md](cosmetics.md)
  - แท็บ "จัดการของแต่งตัว" (ซ่อน/แสดงรายชิ้นในหน้าต่างแต่งตัวของผู้เล่น ราคาเพชรที่ยังไม่ขาย ค่าหน้าตารายชิ้นพร้อมบวก/ลบหลายชิ้น) คือสวิตช์ `cosManage` (ดู: owner และ GM) · `cosManageEdit` (บันทึกซ่อน/ราคา: owner) · ค่าหน้าตาใช้ `cosLook` · เจ้าของตั้ง 2026-11-13 กติกาอยู่ใน [cosmetics.md](cosmetics.md)
  - แท็บ "การ์ด" (ค่าของระบบการ์ดทั้งหมด: กลุ่มช่องและผล 1–3 อย่างของการ์ด 26 ใบ เรทดรอป โอกาสเจาะรู ค่าทอง ราคาขาย เพดานผลรวม · ช่องสีเหลือง = ต่างจากค่าในโค้ด) คือสวิตช์ `cardView` (owner และ GM, เจ้าของตั้ง 2026-11-11) · บันทึกทั้งเซิร์ฟได้เฉพาะสวิตช์ `cardTune` (owner เท่านั้น) · เก็บในตาราง `settings` key `card_tuning` เฉพาะค่าที่ต่างจากในโค้ด (`src/shared/data/cards.ts`) server โหลดตอนเปิดและใช้ทันทีเมื่อบันทึก · โค้ดเกมต้องอ่านค่าผ่าน `cardDef`/`cardNum` ใน `src/shared/cardTuning.ts` · ทุกการบันทึกลงแท็บ "ประวัติ" · ระบบการ์ดในเกมยังไม่ได้ทำ แผนอยู่ใน [docs/plans/card-system.md](../plans/card-system.md)
  - แท็บ "ปรับสมดุล" (ค่าอาชีพ ตัวคูณ ตัวตัดฟื้น และตาราง tier T1–T5 ของทั้งเซิร์ฟ มีผลทันที ลง audit `balance`) คือสวิตช์ `balance` ใน `FEATURE_ROLES` (owner และ GM, เจ้าของตั้ง 2026-11-11) · กติกาอยู่ใน [balance.md](balance.md)
  - แท็บ **"สิทธิ์"** (owner เท่านั้น, ตกลงกับเจ้าของ 2026-11-10, API ใน `server/admin-roles.ts`):
    - ทุก role มีรายการเครื่องมือให้ติ๊ก (ชื่อไทย + คำอธิบาย แบ่งกลุ่ม · `FEATURE_INFO` ใน `src/shared/admin.ts`) ตั้งแต่ไม่กี่อย่างจนถึงทั้งหมด · มีผลทันทีที่ request ถัดไป ไม่ต้องออกจากระบบ
    - เครื่องมือพื้นฐานก็เป็นสวิตช์: `online` (ดูออนไลน์), `charView` (ค้นหา/ดูตัวละคร), `charEdit` (เลเวล/ทอง/เสกของ), `kick`, `teleport` · GM ได้ครบเหมือนเดิม
    - `staffTarget` = แตะบัญชี/ตัวละครของทีมงานคนอื่นได้ (แบน รีเซ็ตรหัส แก้ตัวละคร) · ไม่มี = แตะได้แค่ผู้เล่นธรรมดาและบัญชีตัวเอง · บัญชี owner ไม่มีใครแตะได้เสมอ · GM ไม่มีเป็นค่าเริ่มต้น
    - ค่าเริ่มต้นอยู่ที่ `FEATURE_ROLES` · ตาราง `admin_roles` เก็บเฉพาะที่ owner เปลี่ยนจากค่าเริ่มต้น (`features` = JSON feature → true/false) DB เดิมจึงทำงานเหมือนเดิม และเครื่องมือที่เพิ่มทีหลังได้ค่าตาม `FEATURE_ROLES` · role ใหม่เริ่มแบบไม่มีอะไรเลย
    - สร้าง role: รหัสภาษาอังกฤษ a–z 0–9 _ (2–20 ตัว, เปลี่ยนไม่ได้, ห้าม owner/gm/none/null/admin) + ชื่อที่แสดง (≤ 20 ตัว ห้ามซ้ำ, แก้ได้ = "เปลี่ยนชื่อ") · สูงสุด 20 role
    - `owner` แก้/ลบไม่ได้ · `gm` แก้เครื่องมือและชื่อได้ ลบไม่ได้ · **ลบ role ที่ยังมีบัญชีใช้อยู่ไม่ได้** ต้องเปลี่ยน role ของบัญชีเหล่านั้นก่อน
    - ให้/เปลี่ยน/ถอน role ของบัญชีได้จากแท็บนี้ (ให้ owner ไม่ได้ ตั้งได้จาก command line เท่านั้น · เปลี่ยน role ของ owner ไม่ได้)
    - ป้าย role ในหน้า /admin และชื่อผู้ประกาศใช้ชื่อที่แสดงของ role · ในเกมไม่มีป้าย role (ข้อความแจ้งผู้เล่นตอนถูกแก้ตัวละครยังขึ้นว่า "GM")
    - ทุกการเปลี่ยนลง `admin_audit`: `role-create`, `role-edit` (ชื่อเดิม → ใหม่, เพิ่ม/เอาออก), `role-delete`, `grant`/`revoke` (role เดิม → ใหม่)
  - **ของ owner เท่านั้นตลอด (ไม่มีสวิตช์)**: แท็บสิทธิ์, ประวัติ (audit), รีสตาร์ท/ปิด server, ลบบัญชี/ตัวละคร, ตั้ง owner
