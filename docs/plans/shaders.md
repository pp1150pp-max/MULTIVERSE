## 0. สรุป

เจ้าของเลือก 3 กลุ่ม

| กลุ่ม | ได้อะไร | ภาพใหม่ | ภาระเครื่อง (ประมาณ) |
|---|---|---|---|
| 1. น้ำและทะเลเมฆ | เมฆไหลเอง น้ำท่าเรือมีคลื่นและฟอง บ่อน้ำกระเพื่อม น้ำวนบิดเป็นเกลียว | ทะเลเมฆ 4 ภาพ (เจ้าของเจนใน GPT) | ต่ำ–ปานกลาง |
| 2. ลม | ต้นไม้ หญ้า ธง ใบเรือ โยกเบา ๆ | ธงและใบเรือแยกผ้ากับเสา (เจ้าของเจนใน GPT) · ต้นไม้และหญ้าไม่ต้อง | ต่ำมาก |
| 3. แสงทั้งจอ | ขอบมืด โทนสีตามแมพ หมอกไหล แสงเรือง (bloom) | ไม่ต้อง | ปานกลาง (bloom หนักสุด) |

หลักร่วมของทั้ง 3 กลุ่ม

- **"ปิด" = ภาพเหมือนวันนี้ทุกพิกเซล** ใช้ทางวาดเดิม ไม่ใช่เปิดเอฟเฟกต์แล้วตั้งความแรงเป็น 0
- ยังเป็นงานกระดาษ: การขยับเบา ช้า ขอบคม ไม่เบลอทั้งจอ ไม่ทำให้ดูเป็นน้ำหรือแสงแบบ 3D สมจริง
- เปลี่ยนระดับด้วย uniform ไม่ใช้ `defines` จะได้ไม่ต้อง compile shader ใหม่ตอนเล่น (กันกระตุก)
- ไม่แตะ `src/shared/sim` และ server (ยกเว้นค่าตั้งใน `src/shared`) ไม่เปลี่ยนการชน ระยะตี หรือการเล่น
- ลวดลาย noise สร้างด้วยโค้ดเป็น texture เล็กปูซ้ำ (เช่น 128×128) แทนการคำนวณทุกพิกเซล
- `ShaderMaterial` **ใหม่ที่วาดใน scene** (เช่น ฟ้าในข้อ 2.1) ต้องมี `#include <colorspace_fragment>` ส่วน shader ของ `postFx` ที่อ่านสำเนาจอ**ต้องไม่มี** และ texture สำเนาจอเป็น `NoColorSpace`

## 3. กลุ่ม 2: พืชและธงไหวตามลม

เฟสของแต่ละชิ้นมาจากตำแหน่งในโลก จะได้ไม่โยกพร้อมกันทั้งแมพ มีค่าทิศลม ความเร็ว และความแรงชุดเดียว

### 3.1 ต้นไม้ พุ่มไม้ (sprite)
`Sprite` เป็นสี่เหลี่ยม 4 จุดตายตัว จึง**เอียงยอดได้ (shear) แต่ดัดให้โค้งไม่ได้** ซึ่งเข้ากับงานกระดาษที่โยกจากโคน

```glsl
// ใส่ก่อน "vec2 rotatedPosition;" ใน sprite vertex shader ผ่าน onBeforeCompile
float phase = modelMatrix[3].x * 0.37 + modelMatrix[3].z * 0.53;
alignedPosition.x += sin(uWindTime * uWindSpeed + phase) * uSway * max(alignedPosition.y, 0.0);
```

- material ใช้ร่วมกันต่อ key จึงต้องคิดเฟสจาก `modelMatrix[3].xz` ใน shader (ไม่ตั้งจาก JS) · ตั้ง `customProgramCacheKey` คู่กับ `onBeforeCompile`
- ครอบคลุมทั้ง material ร่วมและ material ของชิ้นที่จางได้/หมุน
- ตารางใหม่ `src/client/swayTable.ts`: key → ชนิดการไหว · ที่ไม่อยู่ในตาราง = นิ่ง
- รายการตั้งต้น: `tree_*` `bush_*` `fern` `tropical_fern` `frost_fern` `ember_fern` `*_shrub_*` `reeds_*` `willow` `swamp_tree_*` `frost_tree` `hibiscus` `coconut_palm_*` `cliff_palm_*` `potted_tree` `hb_palm_pot` `room_*_tree` และ `sea_kelp` (เมื่อ `floor2` รวมแล้ว)
- ไม่มี draw call เพิ่ม · คำนวณ 4 จุดต่อชิ้น

### 3.2 ธง ใบเรือ ราว (ภาพแยกผ้ากับเสา)
ใช้วิธี shear ทั้งภาพไม่ได้ เพราะเสาและตัวเรือจะเอียงตาม (`kraken_flag` `hb_bunting_post` มีเสาในภาพเดียวกัน)
**เจ้าของเลือก (2026-11-26): เจนภาพใหม่ใน GPT แยกส่วนผ้ากับส่วนเสา/ตัวเรือ**

- แต่ละชิ้นได้ภาพ 2 ใบ: ส่วนนิ่ง (เสา ฐาน ตัวเรือ เชือก) และส่วนผ้า (มีขอบโปร่งรอบผ้าพอให้ขยับ)
- `addProp` วาดผ้าเป็น sprite แยกซ้อนหน้าส่วนนิ่งเล็กน้อย (แบบเดียวกับ `PROP_DEPTH_STEP`) · จางตอนบังผู้เล่นและกลับด้านต้องทำทั้งคู่ · ไฟล์แมพไม่ต้องแก้ (key เดิม)
- ผ้าไหวด้วยการเลื่อน UV เป็นคลื่นใน fragment shader ด้านที่ติดเสาแรง = 0 (ด้านไหนติดเสาและตำแหน่งวางผ้ากรอกใน `swayTable.ts`)
- **ภาพเดิมยังเก็บไว้** ใช้ตอนระดับ "ปิด" และใช้อบภาพแผนที่ · ภาพใหม่อาจหน้าตาต่างจากเดิมเล็กน้อย
- ความเสี่ยง: ภาพ 2 ใบจาก GPT อาจซ้อนไม่ตรงกันพอดี ต้องกรอกตำแหน่งเอง หรือเจนใหม่
- ชิ้นที่น่าจะต้องเจน: `flag` `kraken_flag` `skull_flag` `smuggler_flag` `torn_flag` `banner_red` `banner_pole` `hb_banner_pole` `hb_bunting_post` `torn_sail_mast` `ghost_mast` `net` `hb_ship_blue/green/red/white` · ก่อนเขียน prompt ต้องเปิดดูทีละชิ้น ตัดชิ้นที่ไม่มีผ้าออก แล้วเขียน prompt ใน `art_templates/papercraft_maps/WIND_CLOTH.md` (ไฟล์ใหม่)
- ชิ้นที่ยังไม่มีภาพแยก = นิ่ง
- เรือ (`hb_ship_*`): **โคลงทั้งลำ** ราว ±0.5° รอบแนวน้ำ **(เสนอ)** ทำได้เลยไม่ต้องรอภาพ ใบเรือกระเพื่อมเมื่อมีภาพแยก

### 3.3 หญ้าและของเล็กบนพื้น
- `addQuads` ใช้ร่วมกับหน้าผา รอยแตก แผ่นไม้ จึงต้อง**เปิดการไหวเป็นรายการเรียก** เฉพาะ `addDecor` และ `addShoreTufts`
- attribute ใหม่: น้ำหนัก (จุดล่าง 0 จุดบน 1) และเฟสต่อชิ้น · เลื่อนตามแนวขวางของกล้อง
- ของที่วางราบ (`flat`, y ≈ 0.01) น้ำหนัก 0
- แผ่นของเล็กมีหิน เหรียญ ขวด ปนหญ้า → เพิ่มรายการช่องที่ไหวได้ (`sway`) ใน `DECOR` (`src/shared/groundLook.ts` ข้าง `flat`)
- ความเร็ว: คำนวณเพิ่มต่อจุดเล็กน้อย draw call เท่าเดิม

เงาใต้ของและภาพแผนที่อบไม่ไหว (ไม่ต้องแก้)

## 4. กลุ่ม 3: แสงและบรรยากาศทั้งจอ

### 4.1 โครง: ไม่ใช้ `EffectComposer` **(เสนอ)**
`EffectComposer` ใส่แล้วภาพเปลี่ยนแม้ยังไม่เปิดเอฟเฟกต์ใด:

1. พอ scene วาดลง render target (สีแบบ linear) three จะไม่แปลงเป็น sRGB ให้ แล้ว `OutputPass` แปลงทีเดียวตอนท้าย · shader ที่**ไม่มี** `#include <colorspace_fragment>` จะสีเพี้ยน: `HARBOR_FRAG` และ shader ลูกแก้วทั้ง 2 ตัวใน `orbs.ts` (`GROUND_FRAG` กับ `DEBRIS_FRAG` มีแล้ว)
2. การผสมสีโปร่งและแบบ additive ย้ายจาก sRGB ไป linear → แสง ออร่า หมอก เงา ดูต่างจากเดิมทุกชิ้น
3. สีน้ำท่าเรือที่เจ้าของปรับไว้ด้วยตาจะเปลี่ยน

ทางที่เสนอ: ไฟล์ใหม่ `src/client/postFx.ts` ทำงาน**หลัง** `renderer.render` เดิม

| ระดับ | ทำอะไร |
|---|---|
| ปิด | ไม่เรียก `postFx` เลย |
| ต่ำ | วาดแผ่นเต็มจอทับ 1 รอบด้วยการผสมสี (ขอบมืด + ย้อมโทน) ไม่อ่านภาพจอ ไม่มี render target |
| สูง | คัดลอกภาพจอ (`copyFramebufferToTexture`) แล้วปรับสี + ขอบมืด + บวกแสงเรือง |

ภาพจอที่คัดลอกยังเป็นค่า sRGB เดิม จึงไม่ต้องแก้ shader เก่า (**ต้องลองจริงใน PR** รวมบนมือถือ)
ถ้าลองแล้วไม่ผ่านและต้องใช้ `EffectComposer`: ปิด = ข้าม composer ทั้งหมด, เพิ่ม `colorspace_fragment` ใน 3 shader ข้างบน, ตรวจเอฟเฟกต์ additive ทุกไฟล์ และให้เจ้าของเทียบภาพก่อน/หลังก่อน merge

### 4.2 ขอบมืด (vignette)
มืดเบา ๆ ที่มุมจอ ค่าความแรงใน /admin · เบาพอให้ยังเห็นวงเตือนของบอสที่ขอบจอ

### 4.3 โทนสีตามแมพ
- ใช้ค่าเป็นตัวเลข: สีย้อม, ความแรง, ความอิ่มสี, ความสว่าง · ไม่ใช้ภาพ LUT เพราะปรับด้วยแถบเลื่อนใน /admin ไม่ได้
- ต่ำ = ย้อมสีอย่างเดียว · สูง = ครบ 4 ค่า
- ค่าเริ่มต้นทุกแมพ = ไม่ย้อม ยกเว้นรายการแรก **`smugglers_cove` ตอนเย็นส้มอมชมพู** (ตาม `FLOOR2_SKY.md`) ที่เหลือเจ้าของปรับเอง

### 4.4 หมอก
- **ไม่ใช้ `scene.fog`:** กล้อง ortho มุม isometric ทำให้ความลึกในพื้นที่เล่นต่างกันน้อย และ shader ที่เขียนเองไม่รองรับ
- ต่ำ: sprite หมอกเดิม
- สูง: ให้ sprite หมอกไหลเป็นริ้วด้วย noise + ความหนาปรับต่อแมพ
- ต้องไม่ปนกับ**หมอกผีของกัปตันเรือคนตาย** (`hazards.ts` เป็นกลไกเกม) · ในห้องบอสไม่เพิ่มความหนา

### 4.5 แสงเรือง (bloom)
- ถ้า bloom ตามความสว่างทั้งจอ **กระดาษขาวจะเรืองหมด** (ทะเลเมฆ หิมะ ลูกแก้วขาว)
- **เรืองเฉพาะของที่เป็นแสง (เจ้าของเลือก 2026-11-26):** ติด layer ให้ของแบบ additive (ประตู คบไฟ ลาวา ออร่า แสงลูกแก้ว อนุภาค) → วาดเฉพาะ layer นั้นลง target ครึ่งจอ (ตั้ง `scene.background` เป็น `null` ชั่วคราว) → เบลอ → บวกทับ
  - ข้อจำกัด: รอบนั้นไม่มีของบัง แสงหลังต้นไม้อาจทะลุ ต้องตั้งความแรงต่ำและลองดู · อนุภาค three.quarks ต้องตรวจว่าติด layer ได้
- ถ้าลองแล้วแสงทะลุของจนรับไม่ได้ กลับมาถามเจ้าของก่อนเปลี่ยนวิธี (ทางสำรองคือเกณฑ์ความสว่างทั้งจอ ซึ่งคุมของขาวยาก)
- ทำเฉพาะระดับ**สูง** ต่ำไม่มี bloom (`UnrealBloomPass` เบลอหลายชั้น หนักเกินสำหรับมือถือ)

### 4.6 รายละเอียดที่ต้องทำด้วย
- ปรับขนาด target ใน `resize` ตัวเดิมของ `Game`
- `renderer.compile` เฟรมแรกไม่ครอบคลุม pass ใหม่ → วาด `postFx` 1 ครั้งหลังจอโหลด
- หน่วยความจำเพิ่ม (ประมาณ): จอ 1920×1080 สำเนาจอราว 8 MB + target bloom ราว 2–4 MB

## 5. ระดับคุณภาพในตั้งค่าผู้เล่น

เพิ่มแถวใหม่ในหน้าต่าง **เมนู → กราฟิก** (`gfxPanel.ts`) แยกจาก "คุณภาพอนุภาค" ชื่อ **"น้ำ ลม และแสง": สูง / ต่ำ / ปิด**

| อย่าง | ปิด | ต่ำ | สูง |
|---|---|---|---|
| ทะเลเมฆ | เหมือนเดิม | ไหลเอง | 2 ชั้น + บิดขอบ |
| น้ำท่าเรือ | เหมือนเดิม | 2 ชั้นเลื่อน | + คลื่น ฟอง ประกาย |
| บ่อน้ำ/ลาวา | เหมือนเดิม | เหมือนเดิม | กระเพื่อม |
| น้ำวน | หมุนแบบเดิม | + แถบสว่าง | + เกลียวบิด |
| ต้นไม้ | นิ่ง | ไหว | ไหว |
| หญ้า ธง ใบเรือ เรือ | นิ่ง | นิ่ง | ไหว |
| ขอบมืด โทนสี | ไม่มี | ขอบมืด + ย้อมสี | ครบ |
| หมอก | เหมือนเดิม | เหมือนเดิม | ไหลเป็นริ้ว |
| bloom | ไม่มี | ไม่มี | มี |

- เก็บใน `gfxPrefs` (`mv.gfx` ในเครื่องผู้เล่น) · ยังไม่เคยเลือก = ใช้ค่าเริ่มต้นของ /admin · ไม่เกินเพดานของ /admin
- ค่าเริ่มต้น (เจ้าของเลือก): คอม = สูง · จอสัมผัส (`isTouchMode()`) = ต่ำ · **แถวเดียว** คุมทั้ง 3 กลุ่ม
- เบราว์เซอร์วาดด้วย CPU (`checkGpu` ตรวจอยู่แล้ว) → บังคับปิด **(เสนอ)**
- มีผลทันที ไม่ต้องโหลดเกมใหม่
- ข้อความใหม่ต้องเพิ่มคำแปลใน `src/shared/i18n/en/`

## 7. มือถือและความเร็ว

อ้างอิง [`MOBILE_PLAN.md`](MOBILE_PLAN.md) หัวข้อ 7

- PR 6 ของแผนมือถือเสนอ "คุณภาพกราฟิก" ต่ำ/กลาง/สูง = pixel ratio 1 / 1.5 / 2 **ยังไม่ได้ทำ** (โค้ดยังเป็น `min(dpr, 2)`) · ภาระของแผนนี้โตตามจำนวนพิกเซล · เจ้าของให้**แยกเรื่อง** ทำใน PR 6 ของแผนมือถือ ไม่อยู่ในแผนนี้
- ลำดับภาระจากหนักไปเบา: bloom > คัดลอกภาพจอ (ชิปมือถือแบบ tile เสียเวลาตรงนี้) > ฟ้า 2 ชั้นเต็มจอ > แผ่นทับเต็มจอ > น้ำ > ลม
- ระดับต่ำออกแบบให้เพิ่มแค่แผ่นเต็มจอ 1 รอบ + การคำนวณต่อจุดของลม
- เวลาที่ส่งเข้า shader ให้วนรอบ (เช่นทุก 1 ชม. ตามคาบของคลื่น) กันความละเอียดเพี้ยนบนมือถือเมื่อเล่นนาน
- หน่วยความจำ iOS จำกัด: คืน target และ texture เมื่อเปลี่ยนแมพ/เปลี่ยนระดับ (`World.dispose`)
- แผนนี้ไม่ได้ทำ "พื้นลายเดียวในคุณภาพต่ำ" ที่แผนมือถือพูดถึง

**วิธีวัดในทุก PR:** FPS เฉลี่ยและ `renderer.info.render.calls` เทียบ ปิด/ต่ำ/สูง ที่เมืองกลาง ท่าเรือ และแมพ 4 บนคอมของเจ้าของ + มือถือจริงถ้ามี · เกณฑ์ผ่าน **(เสนอ)**: ต่ำ ช้าลงไม่เกิน 10% · สูง บนคอมยังได้ 60 FPS
