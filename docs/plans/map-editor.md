# แผน: ตัวแก้แมพ (Map Editor) ในหน้า `/admin`

สถานะ: **ร่าง รอเจ้าของอนุมัติ** (ยังไม่มีโค้ด) · เขียน 2026-11-20 · แก้ตามคำตอบเจ้าของ 5 ข้อแล้ว (ดูข้อ 6)

## 0. ปัญหาและเป้าหมาย

ตอนนี้แมพทุกใบ "เกิดจากโค้ด": `zones.ts` ให้ path/portal/ทะเลสาบ, `scatterZone()` สุ่มมอนด้วย seed, `Terrain.placeProps()` สุ่มต้นไม้ก้อนหินด้วย seed, `Terrain.placeTown()` วางบ้านเมืองกลางด้วยเลขที่เขียนตายตัว, shader พื้นใน `world.ts` วาดทางเดินและธีมจากค่าเหล่านี้ ผลคือขยับบ้านหลังเดียวต้องให้ AI แก้โค้ดแล้ววนตรวจหลายรอบ (PR #337, #343, #354)

**เป้าหมาย:** เจ้าของลากวางอาคาร ของประดับ NPC ประตู จุดเกิดมอน และเขตเดินได้บนแมพทั้งเมืองและฟาร์ม (ชั้น 1 และชั้น 2) ด้วยเมาส์ใน `/admin` แล้วกดบันทึก ข้อมูลเก็บเป็น JSON ที่ server และ client อ่านแทนค่าในโค้ด โดย **หน้าตาและพฤติกรรมเกมตอนเริ่มต้นต้องเหมือนเดิมทุกพิกเซล**

**ไม่อยู่ในขอบเขต:** วาดพื้น/กระเบื้องแบบ tile paint, ทำภาพกระดาษใหม่ (เจ้าของเจนเอง), แก้ห้องบอส (ใช้ค่าจากแมพแม่เหมือนเดิม), แก้สถิติมอนสเตอร์ (มีหน้า balance อยู่แล้ว)

## 1. รูปแบบ JSON และการย้ายข้อมูลเดิม

### 1.1 หลักคิด: "อบ" ผลที่ generator สร้างเก็บเป็น JSON

ไม่เขียนข้อมูลใหม่ด้วยมือ แต่รัน generator เดิม (`Terrain`, `scatterZone`, `hubLoners`, `placeTown`) **หนึ่งครั้ง** ด้วยสคริปต์ `tools/bake_maps.ts` แล้วเขียนผลออกมาเป็น JSON ทุกชิ้น หลังจากนั้นเกมอ่านจาก JSON อย่างเดียว ไม่เรียก generator ตอนรัน (ลดโค้ดสุ่มลงทีหลัง) generator ยังอยู่เป็นปุ่ม "สุ่มเติม" ในตัวแก้ (สุ่มต้นไม้ในกรอบที่เลือก) ไม่ใช่ทางหลักอีกต่อไป

**กันหน้าตาเปลี่ยน:** เทสต์ `tests/map-bake.test.ts` สร้าง Terrain แบบเก่ากับแบบอ่านจาก JSON แล้วเทียบ `props`, `colliders`, `spawns`, `portals`, `npcPos`, `restSpots` ต้องเท่ากันทุกค่า (ทุกโซน ทุก seed) ผ่านแล้วค่อยสลับ client ให้อ่าน JSON ได้ จุดที่เป็นภาพล้วน (shader พื้น หมอก หิมะ หน้าผา) ไม่ย้าย ยังคำนวณจาก path/theme/lake เหมือนเดิม

### 1.2 ไฟล์

`src/shared/data/maps/<zoneId>.json` หนึ่งไฟล์ต่อแมพ (nexus_city, emerald_forest, misty_marsh, frost_reach, ashen_isle, และของชั้น 2) + `src/shared/mapSchema.ts` (type + `validateMap()` ใช้ทั้ง editor, server, เทสต์) ห้อง boss ไม่มีไฟล์ ยังสร้างจากแมพแม่ (`bossRoom()`)

### 1.3 โครงสร้าง (v1)

```jsonc
{
  "schema": 1,
  "id": "nexus_city",
  "floor": 1,
  "rev": 0,                       // เพิ่มทุกครั้งที่ publish
  "zone": {                       // ค่าที่เคยอยู่ใน ZoneDef (ไม่รวมสถิติ/บูสต์ ที่ยังอยู่ในโค้ด/หน้า balance)
    "half": 69, "theme": "forest", "quadrants": ["forest","marsh","volcano","snow"],
    "start": {"x":0,"z":0}, "safe": {"x":0,"z":0,"half":15}
  },
  "paths": [ {"id":"main","w":4.2,"pts":[[-58,-58],[0,0],[58,58]]} ],   // path + branches
  "water": [ {"kind":"ice","x":-32,"z":34,"rx":12,"rz":9} ],            // iceLakes / lavaPools
  "props": [
    {"id":"p1","key":"b3_vault","x":-15.2,"z":-6.1,"h":7.4,"rot":0,"flip":false,"fade":true,"solid":{"r":2.1}}
    // rot: องศา 0–359.9 หมุนรอบจุดที่ชิ้นยืน · solid: วงกลม {r} (เดิม) หรือกล่อง {w,d} หมุนตาม rot หรือไม่มี = เดินทะลุได้
  ],
  "blockers": [                   // ขอบเขตที่เดินไม่ได้แบบเส้น (ใหม่): polygon ปิด
    {"id":"b1","pts":[[-20,-20],[-20,-5],[-12,-5]]}
  ],
  "walkable": {"half": 61},       // กรอบเดินได้ (เดิมคือ half-8) แก้ได้เป็น polygon ภายหลัง
  "npcs": [ {"id":"keeper","x":-9.4,"z":-3.2} ],
  "rest": [ {"kind":"fountain","x":0,"z":0} ],
  "portals": [ {"to":"emerald_forest","x":-54.5,"z":-54.5,"minLevel":0} ],
  "spawns": [ {"monster":"green_slime","x":10,"z":4,"radius":2.5,"count":1,"respawn":[6,10]} ],
  "lair": {"boss":"forest_bear","x":-42,"z":-42}
}
```

- พิกัดคือหน่วยโลกเดิม (x, z) ไม่ใช่พิกเซล `id` ของแต่ละชิ้นให้ editor เลือก/undo ได้
- `props.key` ต้องมีใน `SHEET_SPECS` (client) ถ้าไม่มี `validateMap()` ไม่ผ่าน
- `h` (ความสูงที่วาด) และ `solid.r` เก็บเป็นค่าต่อชิ้น ค่าตั้งต้นมาจากแคตตาล็อก (1.4)
- เมืองชั้น 2 (harbor, `data/harbor.ts` บน branch `floor2`) ใช้ schema เดียวกัน: `placeTown` ของมันก็ถูกอบเหมือนกัน

### 1.4 แคตตาล็อกของวาง

`tools/build_prop_catalog.ts` สแกน `SHEET_SPECS` + `public/assets/sprites/paper/props/` แล้วสร้าง `src/shared/data/propCatalog.json`: ชื่อ key, หมวด (อาคาร/ต้นไม้/หิน/ตลาด/ป้าย/อื่นๆ), ขนาดภาพ, `h` ตั้งต้น, `solid.r` ตั้งต้น, ชุดหน้า-หลัง (`*_front`/`*_back`) ตามที่โค้ดใช้อยู่ ไฟล์นี้สร้างซ้ำได้ ไม่ต้องแก้มือ ภาพกระดาษใหม่ที่เจ้าของเพิ่มเข้า `sprites/paper/props/` จะโผล่ในคลังหลังรันสคริปต์ (หรือปุ่ม "รีเฟรชคลัง" ใน editor)

## 2. หน้าตาและการใช้งานตัวแก้

แท็บใหม่ **"แมพ"** ในหมวดเนื้อหาของ `/admin` (ทำตามแบบ `src/admin/tabs/*`)

### 2.1 โครงหน้าจอ

- **ซ้าย:** เลือกแมพ (เมืองกลาง / ฟาร์ม 1–4 / ชั้น 2) · เลือกเลเยอร์ (ของวาง, NPC, ประตู, จุดเกิดมอน, ขอบเขต, ทางเดิน/ทะเลสาบ) พร้อมปุ่มซ่อน/ล็อกต่อเลเยอร์
- **กลาง:** canvas มุมมอง isometric แบบเดียวกับเกม (ใช้สูตรฉายภาพ `ISO_DIR`/`CAM_RIGHT` ชุดเดียวกัน ย้ายไปไฟล์ shared เล็กๆ ให้ทั้งสองฝั่งใช้) วาดพื้นสีตามธีมแบบง่าย + ภาพกระดาษจริงของทุกชิ้น + วงกลม collision โปร่งใส + กริด
- **ขวา:** คลังภาพกระดาษ (ค้นหา, แยกหมวด, ภาพย่อ) และกล่องคุณสมบัติของชิ้นที่เลือก (x, z, h, flip, solid r, ลบ)
- **บน:** บันทึกร่าง · Undo/Redo · Snap · พรีวิวในเกม · เผยแพร่ · สถานะ (ร่างต่างจากที่เผยแพร่กี่ชิ้น)

### 2.2 การใช้งาน

| งาน | วิธี |
|---|---|
| วาง | ลากจากคลังลงแมพ (ภาพจางตามเมาส์ก่อนปล่อย) |
| ย้าย | ลากชิ้นที่เลือก, ปุ่มลูกศรขยับทีละช่อง snap |
| เลือกหลายชิ้น | ลากกรอบ / Shift คลิก แล้วย้ายพร้อมกัน |
| หมุน | **หมุนได้อิสระ 360°** (ช่องกรอกองศา + แถบเลื่อน + ลากที่จับหมุนบนชิ้น, ถือ Shift = snap ทีละ 15°) หมุนทั้ง **ภาพ** (เอียงภาพแบนบนจอ) และ **วง/กล่อง collision** ไปด้วยกัน มี flip และปุ่มสลับด้านหน้า/หลังของชุดภาพเพิ่ม · polygon ขอบเขตหมุนได้เช่นกัน |
| ลบ | Delete / ปุ่มถังขยะ |
| ทำสำเนา | Ctrl+D |
| Snap | สวิตช์ + ขนาดช่อง 0.5 / 1 / 2 หน่วยโลก, snap เข้าหาขอบชิ้นข้างเคียง, ถือ Alt = ปิดชั่วคราว |
| Undo/Redo | Ctrl+Z / Ctrl+Y เก็บเป็นคำสั่ง (command stack) ลึก 200 ขั้น ทุกการกระทำ (วาง ย้าย ลบ แก้ค่า) เป็นหนึ่งคำสั่ง |
| ขอบเขต collision | เครื่องมือ "ขอบเขต": คลิกจุดต่อกันเป็น polygon ปิด, ลากจุดมุมแก้, ลบจุด/ทั้งก้อน · แสดงสีแดงโปร่ง · ปุ่ม "แปะวงกลมตามชิ้น" เปิดดูวง collision ทุกชิ้นเพื่อตรวจบ้านทับธงโดยไม่ต้องเดา |
| ทางเดิน/ทะเลสาบ | เครื่องมือเส้น (pts ของ path) และวงรี (iceLakes/lavaPools) ลากจุดแก้ได้ |
| จุดเกิดมอน | วางวงกลมรัศมี เลือกชนิดมอนจากรายการเดิม ตั้งจำนวน/เวลาเกิดใหม่ |
| NPC, ประตู | ลากหมุดที่มีชื่อ (NPC หนึ่งตัวมีหมุดเดียว) ประตูเลือกปลายทางและเลเวลขั้นต่ำ |
| ตรวจ (ปุ่ม "ตรวจแมพ") | รัน `validateMap()`: ชิ้นซ้อนทับกันเกินกำหนด, มอน/NPC/ประตูอยู่ใน collision, ประตูเดินถึงจากจุดเริ่มไม่ได้ (BFS บนตาราง), key ภาพไม่มี, ชิ้นอยู่นอกกรอบ แสดงเป็นรายการคลิกแล้วกระโดดไปชิ้นนั้น |

**หมายเหตุเรื่อง "หมุน" (เจ้าของเลือก 360° แล้ว):** ภาพกระดาษเป็นภาพแบนที่หันหน้าเข้ากล้อง การหมุนจึงเป็นการเอียงภาพบนจอ ไม่ใช่เห็นด้านข้างบ้านจริง มุมเล็กๆ ดูปกติ แต่บ้านหลังใหญ่ที่หมุนมากจะดูเหมือนสติกเกอร์เอียง ตัว collision หมุนตามจริงเสมอ (ใช้ได้ดีกับกำแพง รั้ว สะพาน ป้าย) ต้องใส่ข้อจำกัดนี้ในคำอธิบายของเครื่องมือ ฝั่งเกมต้องรองรับมุมของสไปรต์ (`SpriteMaterial.rotation` ใน three.js) และเงาของชิ้นนั้นหมุนตาม ทำใน PR 3

### 2.3 พรีวิว

1. **พรีวิวในหน้า (ทันที):** canvas ของ editor วาดภาพกระดาษจริง ไม่ใช่ที่กลมๆ
2. **พรีวิวในเกม:** ปุ่ม "ทดลองเดิน" เปิดเกมแท็บใหม่ด้วย `?previewMap=<id>` เกมโหลดร่างของเจ้าของ (ต้องใช้ admin token) แทนค่าเผยแพร่ เห็นเงา หมอก shader พื้น และเดินชน collision จริง ผู้เล่นคนอื่นไม่เห็นร่าง

## 3. การเก็บข้อมูลและการเผยแพร่

### 3.1 เก็บที่ไหน: **ฐานข้อมูล (ตาราง `map_layouts`) + ไฟล์ JSON ใน repo เป็นค่าตั้งต้น**

**อธิบายแบบละเอียด:** ข้อมูลแมพอยู่ได้ 2 ที่ และเกมเลือกใช้ตามลำดับนี้

1. **ไฟล์ใน repo** `src/shared/data/maps/<zoneId>.json` (ค่าตั้งต้น): ถูก build เข้า bundle ของเกมและ server ทุกเครื่องมีเหมือนกัน เทสต์/CI ตรวจได้ git เก็บประวัติให้ ข้อเสียคือแก้แล้วต้อง commit → PR → merge → build → รีสตาร์ต server ไม่เหมาะกับการขยับบ้านทีละนิด
2. **ฐานข้อมูล** ตาราง `map_layouts` ใน SQLite ตัวเดียวกับบัญชีผู้เล่น (`server/data/multiverse.db` บน VPS อยู่ในระบบสำรองเดิม `backup.ts`): เก็บ **เฉพาะแมพที่เจ้าของแก้** คอลัมน์ `zone_id, rev, json, status ('draft'|'published'), author, note, updated_at` ร่างมีหนึ่งแถวต่อแมพ (autosave เขียนทับ) ส่วนที่เผยแพร่แล้วเพิ่มเป็นแถวใหม่ทุกครั้ง เก็บย้อนหลัง 20 revision ต่อแมพ
3. **ตอนเกมโหลดแมพ:** ถ้ามีแถว `published` ของแมพนั้นใช้ rev ล่าสุด ถ้าไม่มีใช้ JSON ใน repo (เหมือน settings เดิมที่ "ไม่มีแถว = ค่าในโค้ด") ถ้าสวิตช์ `/admin` "ใช้แมพจาก DB" ปิดอยู่ ก็ใช้ JSON ใน repo เสมอ เป็นทางหนีฉุกเฉิน
4. **ทำไมไม่เลือกอย่างใดอย่างหนึ่ง:** ไฟล์อย่างเดียว = เจ้าของแก้เองไม่ได้ ต้องพึ่ง AI/PR ทุกครั้ง ซึ่งคือปัญหาที่อยากแก้ · DB อย่างเดียว = dev เครื่องใหม่/CI/เทสต์ไม่มีข้อมูลแมพ และ git ไม่เห็นประวัติ จึงเก็บทั้งสองและมีปุ่ม **"ส่งออกเข้า repo"** ดึง JSON ที่เผยแพร่แล้วมาเป็นไฟล์ให้ commit เป็นค่าตั้งต้นใหม่ (ไม่บังคับ แต่ควรทำเป็นระยะ)
5. **ความปลอดภัยของข้อมูล:** ร่างไม่กระทบผู้เล่น · JSON ต่อแมพราว 100–300 KB (ประมาณการ) ใส่ SQLite สบาย · `validateMap()` รันซ้ำที่ server ก่อนเผยแพร่เสมอ เผยแพร่แมพพังไม่ได้ · สำรองมากับ DB อยู่แล้ว

| | ไฟล์ใน repo อย่างเดียว | ฐานข้อมูลอย่างเดียว | **ผสม (เลือก)** |
|---|---|---|---|
| เจ้าของแก้แล้วใช้ได้เลย | ไม่ได้ ต้อง commit/PR/deploy | ได้ | ได้ |
| ไฟล์ถูกตรวจ/เทสต์ใน CI | ได้ | ไม่ได้ | ได้ (ค่าตั้งต้น) |
| มีประวัติ/ย้อนกลับ | git | ตาราง revision | ทั้งสอง |
| ตรงกับระบบเดิม | – | settings "เก็บเฉพาะที่ต่างจากโค้ด" | **ตรง** |

### 3.2 ใครแก้ได้

- สิทธิ์ใหม่ `map_edit` ในหมวดสิทธิ์ของ `FEATURE_GROUPS` (`src/shared/admin.ts`) ตั้งต้นให้ role `owner` และ `gm` (เจ้าของเลือก; ทั้งสองเป็น role ที่มีอยู่แล้วใน `src/shared/admin.ts`) role อื่นเปิดให้ได้ที่หน้า Permissions เอง · "ย้อนกลับ" และ "ส่งออกเข้า repo" ให้ owner เท่านั้นตั้งต้น ปรับได้ที่หน้า Permissions
- ทุกการ "บันทึกร่าง/เผยแพร่/ย้อนกลับ" ลง `admin_audit` (ใคร แมพไหน rev ไหน เปลี่ยนกี่ชิ้น)
- ผู้เล่นทั่วไปไม่เห็นร่าง และไม่มี API เขียนนอกจาก endpoint ที่ตรวจสิทธิ์

### 3.3 เผยแพร่เข้าเกมจริง

1. **บันทึกร่าง** (autosave ทุกครั้งที่แก้ + ปุ่ม) → `PUT /api/admin/maps/:id/draft` ตรวจ `validateMap()` ฝั่ง server ซ้ำ ไม่ผ่านก็เก็บร่างได้ แต่เผยแพร่ไม่ได้
2. **เผยแพร่:** ปุ่มต้องกดยืนยันและแสดงสรุปการเปลี่ยน (เพิ่ม/ลบ/ย้ายกี่ชิ้น) → ตั้ง `status=published`, `rev+1`
3. **server (เจ้าของเลือก):** publish แล้ว **ห้องใหม่ใช้ทันที ห้องที่มีคนอยู่ใช้ตอนผู้เล่นเข้าแมพนั้นครั้งถัดไป** ไม่เปลี่ยนใต้เท้าคนที่ยืนอยู่ จึงไม่มีบ้านงอกทับตัวละคร ไม่ต้องรีสตาร์ต server: ตอนสร้าง Sim/ช่องใหม่ server อ่าน rev ล่าสุดจาก `MapRegistry` ปุ่ม "เผยแพร่แล้วรีสตาร์ตทันที" (ใช้ `stop-server --restart` เดิม) เป็นทางเลือกเสริมเมื่ออยากให้ทุกคนเห็นพร้อมกัน
4. **client:** เหมือน `LOOK_PATH` เดิม: ก่อนโหลดภาพเรียก `GET /api/maps` ได้ `{id: rev}` ทั้งหมด แล้วโหลด `GET /api/maps/:id?rev=N` (แคชตาม rev) ไม่มี rev ใหม่ก็ใช้ JSON ที่ bundle มา เซสชันที่เปิดค้างเห็น rev ใหม่เมื่อเปลี่ยนแมพครั้งถัดไป
5. **ย้อนกลับ:** รายการ revision ในแท็บ กดกลับไป rev ก่อนหน้าแล้วเผยแพร่ซ้ำ

### 3.4 สิ่งที่ต้องแก้ในโค้ดเกม (ผลข้างเคียงที่ต้องระวัง)

- `ZONES` และ `Terrain` ตอนนี้สร้างตอนโหลดโมดูลแบบ synchronous ต้องเพิ่มชั้น `MapRegistry.get(id)` ที่ client ใส่ค่าหลัง fetch และ server ใส่ตอนบูต โดย `Terrain` รับ `MapData` เป็นอาร์กิวเมนต์แทนการสุ่มเอง
- `Terrain.isBlocked`/`resolve` เพิ่มการเช็ค polygon (blockers) และ `pathfind.ts` ฝั่ง client ต้องอ่านชุดเดียวกัน ไม่งั้นตัวละครเดินชนกำแพงที่ pathfind มองไม่เห็น
- เพิ่มค่า `/admin` ตามกฎเจ้าของ: สวิตช์ "ใช้แมพจาก DB" (ปิด = ใช้ JSON ใน bundle ทางหนีฉุกเฉิน), ขนาดช่อง snap ตั้งต้น, ระยะซ้อนทับสูงสุดที่ validate ยอมรับ

## 5. ทางเลือกที่ไม่เลือก

**Tiled (โปรแกรมแก้แมพภายนอก, ไฟล์ .tmx/.json)**
- ออกแบบมาสำหรับแมพกระเบื้อง (tile grid) แต่แมพเรา "วางชิ้นอิสระบนพื้นต่อเนื่อง" ไม่มี tile ต้อง map object layer เองทั้งหมด จึงเหลือประโยชน์แค่ UI
- เจ้าของต้องติดตั้งโปรแกรมอีกตัวและย้ายไฟล์ไปมา ไม่อยู่ใน `/admin` ซึ่งขัดกฎ "ทุกอย่างตั้งค่าใน /admin"
- ไม่รู้จักภาพกระดาษ, SHEET_SPECS, สิทธิ์, audit, validate กฎเกม (ประตู/มอน/collision) ต้องเขียน importer + validator เองอยู่ดี ซึ่งงานพอๆ กับเขียน editor เอง แต่ได้ประสบการณ์ที่แย่กว่า

**ภาพฉากหลังภาพเดียว (วาดทั้งแมพเป็นภาพใหญ่ภาพเดียว แล้วลง collision แยก)**
- แก้ตำแหน่งชิ้นเดียวต้องเจนภาพทั้งแมพใหม่ (เจ้าของเจนเองจาก GPT: ช้า แพง สไตล์เพี้ยนระหว่างรอบ) แย้งกับเป้าหมาย "ขยับของเองได้"
- เงา การซ้อนหน้า-หลัง (ผู้เล่นเดินหลังบ้านแล้วบ้านจาง) และ collision ต้องมีวัตถุแยกชิ้นอยู่ดี ภาพเดียวทำไม่ได้โดยไม่แยกชั้นเอง
- ภาพใหญ่หนัก โหลดช้า โดยเฉพาะมือถือ (ดู MOBILE_PLAN) และขัดกับระบบหลายธีม/ควอดแรนท์ของเมืองกลาง
